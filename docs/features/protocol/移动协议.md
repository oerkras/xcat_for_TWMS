## 1. 结论（实锤）

移动路径权威在 **`MovePath`（`fd62a654…`）**：

| 方法 | RVA | IDA 名 | 方向 |
|---|---|---|---|
| `OnMovePacket(InPacket, isPassive=false)` | `0x11A0490` | `MovePath_OnMovePacket` | **S→C 收包应用** |
| `Decode(InPacket, …)`（private） | `0x119D290` | `MovePath_ParseMove_private` | 被 OnMovePacket 调用 |
| `Flush(OutPacket, bFly, …)` | `0x1198DC0` | `MovePath_Flush` | **C→S 上报**（飞/走都走这里） |
| `Encode(OutPacket)` | `0x119AB50` | `MovePath_Encode` | Flush 内部序列化 |

CMS / TW 同布局：`_x/_y@0x10/0x12`，`_vx/_vy@0x14/0x18`，`Elem@0x30`；`MovePath` 挂在 `VecCtrl+0x78`。

## 2. 已钉死的 Recv opcode

| Opcode | Handler | 链路 |
|---|---|---|
| **`0x00D9` (217)** | `OpRecv_00D9_UserOrActor_Move` @ `0x1116B40` | `actor+0x50` → **VecCtrl** → `+0x78` **MovePath** → `OnMovePacket(inPacket, false)` |
| **`0x0112` (274)** | `OpRecv_0112_MovePath` @ `0x111EC50` | 直接/短路径调用 `OnMovePacket` |
| **`0x011A` (282)** | `OpRecv_011A_Move_via_helper` | → `MoveApply_Helper_A7FBD0` → `OnMovePacket` |
| **`0x012F` (303)** | `OpRecv_012F_Move_via_helper` | → `MoveApply_Helper_AB69D0` → `OnMovePacket` |

`0x00D9` 反汇编关键片段：

```text
mov rax, [rdi+50h]      ; VecCtrl* (FieldActorBase)
mov rcx, [rax+78h]      ; MovePath*
mov rdx, rsi            ; InPacket*
xor r8d, r8d            ; isPassive = false
call MovePath_OnMovePacket
```

表：`Dumps/opcode_handler_map.tsv`。
