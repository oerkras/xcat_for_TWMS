## 0. 一句话

经典版「自动召唤宠物」= **场上无可见宠时走官方激活包**（`CashItemManager.SendActivatePetRequest`）。  
**喂食不自建**：游戏已有 `TryConsumePetFood` + 阈值 50；我们只保证宠在场，并可选「有粮才召」以免召出立刻饿死。

## 1. 与枫星差异（勿混）

| 维度 | 枫星（对照） | TWMS 经典版（本仓） |
|------|-------------|-------------------|
| 进程 | `msw.exe` / Artale Lua | `Maplestory_Classic.exe` / Il2Cpp |
| 读态 | Lua `CharacterPetSlot` + Fullness + Summon | `User.m_apPet@0x2B0` + Cash `ItemSlotPet`（字段只读） |
| 召唤 | `_UseController:UseItem(...Cash)` | **`SendActivatePetRequest(nPos)`**（本 feature 主路径） |
| 卸宠 / 鬼宠 | `ReqUnEquipPet` + 12s grace | 首版：**不做**；仅「无激活宠 → 召唤」 |
| 喂食 | 自建 `UseItemByCode(2120000\|2120008)` | **不做**；交给官方 `TryConsumePetFood`（阈值 50） |
| 原生自动喂 | 无对等 | **已有** → 本仓不重复实现（见 §3.4） |
| 配置 | `[pet_feed]` 含阈值/喂食 | 首版只要 `enabled` + 间隔；粮仅作召唤门控 |

## 2. 职责边界

### 做

- 面板「自动召唤宠物」+ `user.ini` 落盘 + payload 轮询生效
- 进图就绪门控：`ports::world::IsPlayReady()`（`IsInMapScene` ∧ WM alive）+ `MyUser` 存活 / 落地后再 Tick
- **自动召唤**：场上 `activatedCount==0` 且 Cash 有可激活活宠 +（建议）有食品 → `SendActivatePetRequest(nPos)`
- 无粮 / 无活宠节流通知（对齐枫星 60s，文案改为召唤相关）
- 场上空宠时加速轮询（~2.5s）
- 与换图 / 未落地 / 禁宠图 的门控

### 不做（非目标 · 首版）

- **自建自动喂食 / 可配喂食阈值**（官方已做；除非以后要 &lt;50 再开可选 P2）
- 宠物吸物 → 见独立 feature [`../pet_loot/模块设计.md`](../pet_loot/模块设计.md)
- 多宠齐召 / 指定槽位策略（首版只保 **≥1 只场上宠**）
- 鬼宠卸装重召
- 伪造 Pet 包 / 改 GA `.text`
- 自动买粮 / 自动复活死宠
- Cash 宠物食品专项

## 3. 经典版逆向锚点（TW · **2026-08-03 remount**）

详细证据见 [`P0a_锚点复核.md`](P0a_锚点复核.md)。  
真源：`Dumps/runtime/out/dump.cs` + IDB `GameAssembly.dll.i64` · imagebase **`0x7FFB74A20000`**。  
**CMS RVA ≠ TW**；字段：`m_apPet` 仍 **`+0x2B0`**（本轮换包未漂）。

### 3.1 场上宠与饱食度（TW）

| 符号 | TW（08-03） | 用途 |
|------|-------------|------|
| `User.m_apPet` | **`+0x2B0`** | 场上宠数组（字段只读计数） |
| `Pet._repleteness` | `+0xBC` | 诊断饱食 |
| `ItemSlotPet.nRepleteness` | `byte @0x38` | 槽位饱食 / 兜底 |
| `ItemSlotPet.dateDead` / `nRemainLife` / `nActiveState` | `+0x40` / `+0x48` / `+0x4E` | 死宠 / 可召过滤 |
| `UserLocal` / `CashItemManager` 哈希 | `ac2e48…` / `edfa536…` | FindAll / Singleton |
| `IsUnableToUsePet` | ⏳ 未钉 | 禁宠图；失败打日志 |

> 读态**不调**混淆的 `GetActivatedPetCount` / `GetRepleteness` RVA（旧包值已过期）。

### 3.2 召唤（激活 · TW）

| 符号 | TW（08-03） | 说明 |
|------|-------------|------|
| **`CashItemManager.SendActivatePetRequest(int nPos)`** | RVA **`0xC56910`** | **主路径**（旧 `0xC58020`） |
| `Canvas.SendWillRenderCanvases`（泵） | RVA **`0x5239AB0`** | 主线程调度 |
| `ClientPacket.UserActivatePetRequest = 110` | （协议观测） | 不手组包 |

召唤前置：

1. 场上 `activatedCount==0`（`m_apPet` 非空计数）
2. 非禁宠图（首版可降级为失败日志）
3. Cash 栏可激活活宠 → `summonPetPos`
4. （可选）有粮才召
5. `SendActivatePetRequest` + pending 5s

### 3.3 喂食（TW · **参考 · 首版不调用**）

官方自动喂已覆盖。旧包（08-01）RVA **未在 08-03 重锚**；P2 再钉。

| 符号 | 旧 RVA（08-01 备查） |
|------|----------------------|
| `UserLocal.TryConsumePetFood()` | `0x101B700` |
| `UserLocal.FindProperPetToEatFood` | `0x109F4D0` |
| `UISlotItem.SendPetFoodItemUseRequest` | `0x5E9790` |

### 3.4 游戏原生自动喂（为何我们不重复）

`UserLocal`（TW `ac2e48…`，L70163+）已内建：

| 常量 / 字段 | 值 | 含义 |
|-------------|-----|------|
| `PetRepletenessAutoEat` | **50** | 原生自动进食阈值 |
| `PetConsumeFoodCheckTime` | 1000 ms | 原生检查间隔 |
| `PetConsumeFoodNoItemMsgTime` | 60000 ms | 无粮提示间隔 |

决策：**喂食交给官方**；本 feature 只负责召唤。

### 3.5 风控

| 能力 | 约束 |
|------|------|
| GRAP | 禁止改 `.text`；只调 Il2Cpp 方法 / 读字段 |
| 发包频率 | 召唤 pending **5s**；空宠轮询 ~2.5s |
| 禁宠图 | 失败只打日志不刷包 |
| 死指针 | `MyUser` 名校验 + 存活探测 |
| 主线程 | Activate 走 SendWill 泵 |

## 4. 目标架构（召唤-only）

```text
xcat_app（勾选「自动召唤宠物」+ 间隔s）
  → WritePetFeed / WritePayloadControl
x/ipc::Poll
  → pet_feed::SetConfig
x/features/pet_feed::Tick
  → ports::pet::ReadState()   # activated / food门控 / summonPetPos
  → 门控：未落地 / nolp / 禁宠图
  → activated==0 && hasFood && summonPetPos → Activate(nPos) + pending 5s
  → 无粮/无活宠 → 60s 警告
  → activated>=1 → idle（喂食交给官方）
```

Tick 决策树：

```text
gated(not landed) → return
ReadState
  nolp → return
  activated>=1 → idle（官方喂）
  activated==0:
    pending → wait
    hasFood && summonPetPos → Activate → pending
    !hasFood → notify(no food)
    !summonPetPos → notify(no living pet)
```

空宠加速：~2.5s；有宠后间隔可拉到 10–30s（仅探活）。

## 5. 配置契约

```ini
[core]
petSummon=1
petSummonRequireFood=1   ; 1=有粮才召（默认开，防召出即饿）
```

| 字段 | 默认 | 说明 |
|------|------|------|
| `petSummon` | 0 | 自动召唤总开关 |
| `petSummonRequireFood` | 1 | 1=有粮才召；0=无粮也召 |

~~`thresholdPct` / `foodCode` 喂食用~~ → 已删；粮扫描仅在勾选「有粮才召」时作门控（仍扫 `212xxxx`）。

## 10. 验收清单

1. 勾选开启 → `user.ini [pet_feed] enabled=1` 落盘
2. 进图无宠、背包有活宠+粮 → ≤数秒内召唤成功，`activatedCount≥1`
3. 手动收宠 → 空场加速轮询后再次召唤
4. 勾选有粮才召且无粮 → 不召唤；60s 级警告一次
5. 禁宠图 → 不召唤、不刷包
6. 关开关 → 立即停止；不残留 pending 乱发包
7. 宠在场后 **不**额外发喂食包（官方自行 ≤50 喂）
8. **无** GA `.text` 修改

## 11. 风险与假设

| 项 | 说明 |
|----|------|
| 偏移漂移 | 换包必重锚 **RVA/类哈希**；字段（如 `m_apPet@0x2B0`）本轮未漂，不保证下次 |
| `nActiveState` 粘滞 | 场上空宠时 `active-stuck` 回退；真过期不 `ignore-dead` |
| `NowNetTicks` | FILETIME 纪元 `504911232…`（勿用 Unix 偏移） |
| Activate timeout | job serial 作废晚到泵 |
| 食品 ID 段 | `212xxxx` 启发式；门控用，不依赖精确 `IsPetFoodItem` RVA |
| 主线程 | `SendActivatePetRequest` 必须走 SendWill 泵，禁止 worker 直调 |
| 官方喂失效 | 若实机发现官方不喂，再开 P2 可选 `TryFeed`；首版不做双通道 |
