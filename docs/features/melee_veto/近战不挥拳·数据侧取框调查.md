# 近战不挥拳 · 数据侧取框调查（Classic TWMS）

> **状态**：⏸ **调查归档**（2026-08-12 21:2x）— 结论已定，探针已关，实现留待以后
> **产品**：新枫之谷：经典版（TWMS / MSC）；**不是**枫星
> **源码**：`x/features/melee_veto/`
> **产物**：`bin/XCat_data/xcat.dll`（CMake `xcat_probe`）
> **基线**：`d41d197`（`melee_veto` 首次提交，可一键回退）
> **结论一句话**：**不要**改 `ActionManager._afterimageMap` 里的框；这张表是全局共享且会被换掉的。

---

## 1. 这轮要回答什么

原问题：近战不挥拳，**一定**要走 inline hook + `.text` patch 吗？
探路方向：能不能只改「取攻击框」的数据，让平砍找不到近身目标，从而自然走出手（远程）分支。

答案：**不必打 `.text`**；但也**不能**改那张共享表。理由见 §4。

---

## 2. 取框链路（零钩子只读游走，已跑通）

```text
Singleton<ActionManager>                       // 父类，classParent 直接给出膨胀后的 klass
  └─ _instance : Lazy<ActionManager>           // static @0x0
       └─ _value → ActionManager
            └─ _afterimageMap @0x40            // Dictionary<string, MeleeAttackAfterImage>
                 └─ MeleeAttackAfterImage.Range @0x18   // Dictionary<int, Rect>
                      └─ [action id] → Rect(16B)        ← 近战找怪用的框
```

关键点：不用自己构造泛型实例化。`Singleton<ActionManager>` 就是 `ActionManager` 的父类，
`classParent` 给出的是已膨胀的 klass，静态区随之可取。

### 真实标识（取自运行时 dump `Dumps/runtime/out/dump.cs`，2026-08-06）

| 角色 | 值 |
|---|---|
| `ActionManager` | `f1275d524fe94bf7c441578d3d7c7bef9e1a0547cc23323474137e6bd93054d`（TypeDefIndex 1653，L73846） |
| `Singleton<T>._instance` | `b9143f0b097da8b3733c3286804b0dee7ab4ae8f39620354bc4817d33fe9a42`（static @0x0，L1065361） |
| `MeleeAttackAfterImage` | `ce1e4383d8bf58ae578e68e930f44125171142c727a967128e50bc55794f425`（TypeDefIndex 1634，L73512） |
| `MeleeAttackAfterImage.Range` | `Dictionary<int, Rect>` @0x18（L73516） |
| `Lazy<T>._value` | 按名解（mscorlib 不混淆）；须落在**膨胀后**的 `Lazy<ActionManager>` 上 |

字典布局：`buckets@0x10 entries@0x18 count@0x20`。
`Dictionary<int,Rect>` entry = `hashCode(4) next(4) key(4) Rect(16)` = 28 字节，Rect 在 entry+12。
与反编译出的 `*(_OWORD *)(entries + 28*i + 44)` 对得上（44 = 数据区 0x20 + 12）。

### 两个踩过的坑（都会让链路整段作废）

1. **类名是混淆哈希，命名空间为空**。按 `Dumps/cms_cw/dump.cs` 里的友好名
   （`Msc.Game.Object.Avatar` / `ActionManager`）去 `FindClass` 永远查不到。
   `cms_cw` 那份是**未混淆参照，只能用来认结构**。仓里既有功能一律写
   `FindClass("", kHash…)`，照惯例来即可。
2. **两份 dump 的字段序不一样**。参照里 `_afterimageMap` 在 `0x48`，实机在 `0x40`
   （参照在它前面多一个字段）。照抄参照偏移会读到隔壁指针，再往下遍历就是野指针。

## 3. 实测证据

### 3.1 整张表（只读印出，两次，中间换了武器）

| 时间 | 条目 | n | action id |

| 21:13:56 | `Character/Afterimage/spear.img/10` | 8 | 10、13、14、15、19、20、21、32 |

swordOL 表全文（`id:(x,y,w,h)`）：

```text
 5:(-88,6,70,56)   6:(-73,-17,78,67)  7:(-102,10,80,40)  8:(-123,1,136,47)
16:(-84,15,64,15) 17:(-83,16,71,14)  18:(-110,11,70,21)
```

**字典是懒建的**：`_afterimageMap` 解出来时 `count=0`，6 秒后才填好。
一次性解析必定空手而归，重试（3 s × 40）不是保险而是必需。

### 3.2 平砍用哪些 id

探针挂在取框函数（RVA `0x1228290`）上纯转发观测，按
`(action id, 是否处在普攻帧)` 分槽，每个组合只记一行。
「普攻帧」= `gNormalMeleeDepth > 0`，该计数只在 `HookMelee` 里 `skill == nullptr`
的分支上加（带技能的调用在上面就原样放行返回了），因此严格等价于
**本地角色、不带技能的近战平砍**。

```text
21:02:51  rect kind=16 帧=普攻 rect=(-84,15,64,15) hits=6
21:02:51  rect kind=17 帧=普攻 rect=(-83,16,71,14) hits=1
```

平砍只用 **16 / 17**，且数值与 swordOL 表逐位吻合 → **框确实来自这块托管内存**，
数据侧可达，不必碰 `.text`。

### 3.3 但 16 / 17 不是平砍专属

```text
21:06:42  rect kind=16 帧=非普攻 rect=(-98,16,68,14) hits=3
21:06:42  rect kind=17 帧=非普攻 rect=(-98,16,62,14) hits=1
```

### 3.4 同一个 id 在不同时刻框不一样

| id | 普攻帧观测 | swordOL 表 | 非普攻帧观测 |
|---|---|---|---|
| 16 | (-84,15,64,15) | (-84,15,64,15) ✓ | (-98,16,68,14) ✗ |
| 5 | — | (-88,6,70,56) | (-90,6,72,66) ✗ |
| 6 | — | (-73,-17,78,67) | (-73,-23,78,73) ✗ |

另有 `kind=9`(-30,-5,30,86)、`kind=11`(-30,-14,30,87) 在**两张表里都不存在**。
即：同时至少有三套框在供数，我们印出来的只是当下缓存里的那一份。

## 4. 结论：不要改这张共享表

`ActionManager` 是全局单例，`_afterimageMap` 是全场角色共用的缓存。往里写零有三个问题：

| 问题 | 证据 |
|---|---|
| 改的表**随时会被换掉**，改动自然失效 | §3.1 两次印表条目完全不同（swordOL → spear） |
| 同一个 id **服务多个调用方**，会连坐 | §3.3 16/17 在非普攻帧也出现 |
| 改的是**全局共享数据**，会波及场上其他角色 | 单例 + 按 afterimage 资源路径为键，非按角色 |

## 5. 建议的实现路径（留待以后）

不打 `.text`、不动共享表：**沿用已在跑的那个取框函数钩子**，在它转发完成之后，
仅当 `gNormalMeleeDepth > 0` 时把这一发的输出框改空。

| 好处 | 为什么成立 |
|---|---|
| 技能碰不到 | 技能路径不进 `gNormalMeleeDepth` 计数 |
| 其他玩家 / 怪碰不到 | 深度是 `thread_local`，别的调用栈上是 0 |
| 不动共享数据 | 只改这一发调用的输出，出帧什么都不留 |
| 关开关即恢复 | 无持久化写入，不需重启 |

代价：保留一个**函数钩子**（不是指令补丁），而这个钩子当前已经在跑。

## 7. 怎么重新打开探针

探针由标记文件闸门控制，**不需要重新构建，也不需要重开客户端**：

```powershell
# 开：放下标记文件，然后把功能开关关一次、开一次
New-Item -ItemType File -Path bin\XCat_data\state\melee_rect_probe -Force
# 关：改名或删除即可
Rename-Item bin\XCat_data\state\melee_rect_probe melee_rect_probe.off
```

用文件而不是环境变量，是因为环境变量得把启动器和客户端整套重开才生效。

槽位是按会话计的：重开客户端后要重新采样。要看技能占用哪些 id，
就在同一会话里逐个技能各放一次，日志会给出 `帧=非普攻` 的那一组。
