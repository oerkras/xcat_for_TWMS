# channel_hop Feature 模块设计（Classic TWMS）

> **状态**：✅ 已挂入 `xcat.dll`（契约 + UI + **直调发包**；结算：离图/InterStage → 软成功；Waiting 硬断即 Fail；成功后 **20s** 冷却 + **4s** 静默再恢复战斗；A8 未置位不进 Waiting）  
> **源码根**：`x/features/channel_hop/` · IPC：`x/ipc/payload_control.*` · 契约：`common/xcat_payload_control.*`  
> **产物**：`bin/XCat_data/xcat.dll`（CMake `xcat_probe`）· UI：`xcat_app/workspace_tabs.cpp`  
> **对照**：枫星 `manualRejoinSeq` / Overlay「随机换频」（**SceneManager.Reload + 命名管道，不可复用**）  
> **产品**：经典版 TWMS · **不是**枫星  
> **安全**：遵守 [`../security/GRAP与枫星对齐.md`](../security/GRAP与枫星对齐.md) — **禁止 E9 / 改 `GameAssembly.dll` `.text`**。  
> **锚点世代**：2026-08-03 remount（代码真源：`channel_hop.cpp`）

## 职责

- 挂机卡「随机换频」按钮与 **F10** → bump `[core] manualRejoinSeq`
- payload 边沿触发后：**不开任何换频菜单** → 读 `WorldManager` 当前频/频道数 → **优先未满频**随机 → `Field.SendTransferChannelRequest`
- 测谎 busy / 非玩法就绪 / 冷却：延后 pending，不丢 seq
- 遇人自动换频由独立 [`../encounter/模块设计.md`](../encounter/模块设计.md) 调用本模块；本模块不内嵌遇人状态机

## 与枫星差异（勿混）

| | 枫星 | TWMS Classic |
|---|---|---|
| 下发 | 优先命名管道 `kIpcManualRejoin`，失败才 bump seq | **仅** `user.ini [core] manualRejoinSeq` |
| 执行 | `SceneManager.Reload` → UGC 随机分频 | **直调** `Field.SendTransferChannelRequest`（无 UI） |
| 模块 | 挂在庞大的 `auto_relogin` | 独立 `channel_hop` |

## 数据流

```
xcat_app 按钮/F10
  → WritePayloadControl(manualRejoinSeq++)
  → ApplyManualRejoinSeq（磁盘 stamp + 进程内 CAS 去重）
  → channel_hop::RequestManualRejoin
  → Selecting：读 WM 频道信息并随机
  → Confirming：Field.SendTransferChannelRequest(target)
  → Waiting / Notify
```

遇人路径：`encounter::RequestHop` → 同 `RequestManualRejoin`（seq 基址 `0xE1000000`），**不**经 UI stamp。

## 逆向锚点

| 项 | TW 实锤（与代码同步） |
|---|---|
| 当前频道 | 内部 **0-based** `nIdx`；UI `ch.N` = `nIdx+1`。优先 **`WM+0x6C` 前进** → `+0x68` 前进 → `gKnownChannelIdx`；冷启动先 6c 再 68 |
| 频道数 | `WorldManager._adultChannel` **`+0x78`** `List<bool>._size@+0x18`；后备 CCU `worldChannelCount` |
| 发包 | `Field.SendTransferChannelRequest(int nIdx)` RVA **`0xBB5200`**（旧 `0xBB6490`，2026-08-03 remount）· **参数 0-based** · 实例 `GetMapScene()` |
| 独占门控 | `WorldManager.CanSendExclRequest` RVA **`0xDD7C10`** · `type=500`（`0x59CA6471+dword@DB94`）· 调用 `r8=r9=0`。读/写 **`WM+0xA8`**（`+0xA0/+0xA4/+0xAC` 旁邻）。BIN：未过则 **无 `op=44`**，settle「满人」是误诊 |
| 警戒 | 短 `IsAlertMode` RVA **`0x12405C0`**（读 `LocalUser+0x114`；与 [`drop_alert_bypass`](../drop_alert_bypass/模块设计.md) 同锚）。**勿用** CFF 兄弟 `0x1242770`（读 `+0xC8`，曾误钉） |
| 硬断 | KickSniff `LastSessionState`：正常迁频 `Connected→Connecting`；异常 `→Disconnected`（BIN seq=18） |

**明确不做**：`UIGameMenu.OnClickButton`、打开 `UIChannelShift`、`SetChannel`、点 `btChange`。

## 控制面

| 项 | 值 |
|---|---|
| INI | `user.ini [core] manualRejoinSeq` |
| core version | `kPayloadControlCoreIniVersion = 20` |
| stamp | `state/lie_ai/last_manual_rejoin_seq.txt`（注入首次 Apply：**默认收养不重放**；若 `ini seq > stamp` 且 `writeTickMs` ≥ 本 DLL 加载时刻 → **放行新点击**；其后进程内 CAS + `seq > last` 边沿） |
| writeTick | `WritePayloadControl` 强制 `writeTickMs` 进程内单调递增（同毫秒连写不被 Apply 跳过；与补给/一键卖同款） |
| UI | 首页挂机卡「随机换频」+ F10 |

## FSM

| 状态 | 动作 |
|---|---|
| Idle | 等 pending；门控通过后 Selecting；defer 时通知一次「排队中」 |
| Selecting | 主线程读 WM 频道信息；选频池 **prefer(登录未满) → neutral(无表) → avoid(满/成人/本轮拒收)**；跳过 `WM._adultChannel` 成人频；日志 `pick-pool` |
| Confirming | 开战先 **停刀 + 压 attack + 临时关 Invuln**；**PreFire settle ≥800ms**（无警戒也等）；若 `IsAlertMode` 再等解除（不烧 attempt，最长 20s），脱战后可再延 800ms；`!CanSendExcl(500)` 等待；`WaitFireIdle` 后 `SendTransfer`；**A8 未置位则软等（1s 退避）、不进 Waiting、不 MarkRejected**；同目标连续 **8 次**或累计 **15s** 仍 A8=0 → 换其它频（仍不 Reject） |
| Waiting | 离图软成功；**Disconnected 立刻 Fail**；`Disconnecting` 持续 ≥3s 才 Fail；见 Connecting 记真迁频；未离图且已确认发包 → 满人换频+Reject；未确认发包 → 换频但不污染 prefer |

门控：`IsPlayReady` · **进图冷却 4s**（自进图/落地起**持续记时**，非点 F10 才起算）· 非 CashShop/Login · `!auto_lie` · 冷却（**成功后 20s** / 失败后 3s）· **换频静默 4s**（settle 后暂缓 resume）。警戒 / excl 均在 Confirming 等（Idle 不 defer，以便先停手）。

开始 hop：`simple_combat` ChannelHop 硬闸 + 压 attack（无敌不再由 hop hold）；结束时延迟 4s resume，若 `encounter::HoldsCombatPause()` 则**不**抢清 pause。对外 `CooldownRemainingMs()` 供遇人挡再 hop（遇人 `kPostHopGraceMs=22s` 与冷却对齐；**停手恢复不绑 22s**，落地采样无人即可 Resume）。

冷却/静默内连点：toast「排队中」后 **保留 pending**，冷却满自动 Begin（不缩短 20s 窗）；静默已结束则先放刀，勿因排队停战斗到冷却满。

满人回退：`kMaxFireAttempts=5`；拒收频写入 CCU 填表 Avoid。成功缓存 `knownIdx`；Login 清缓存与 `gLastRaw68/6c`。toast `ch.(idx+1)`。

**未满优先真源**：进图后无实时每频人数（不开 UIChannelShift）。依赖 auto_enter `PickOpen` 喂入的 `ChannelItem` 填表（`nUserNo`/`ChannelCapacity`/`bAdult`）；无表时退化为原随机（仍跳过成人频）。表会随挂机变旧——拒收回退仍兜底。

## 验收

1. 点按钮 / F10 **不应弹出**游戏换频菜单  
2. 日志 `ChannelHop begin …` → `pick …` → `transfer fired` → `settle ok`  
3. 目标频进不去：日志 `retry … next=`，最多再试到 5 次（含首次）  
4. 连点第二次不应被 Fail 吞掉  
5. 测谎/冷却/警戒 defer 应有「排队中」通知  
6. 战斗警戒中 F10：应 `waiting alert` / 停手，**不应**连烧 3 个频后 Fail；脱战后一次成功  
6b. 无警戒 F10：日志应有 `preFireSettle` / `invuln hold`（若开着）/`attack fire suppressed`，begin→transfer **≥约 800ms**；不应再出现 seq=8 式 ~100ms 内 `Connected→Disconnected`  
7. excl busy / A8 未置位：应 `waiting excl` / `no-packet A8 still 0`，**不应**空烧 attempt、不应 MarkRejected；同目标持续 no-packet 超限应 `retry`/`Fail`（仍不 Reject）  
8. 成功后 20s 内再 F10：应 defer「冷却中（结束后自动换）」并 **hold pending**；冷却满自动 `begin`（不缩短窗）  
8b. settle 后约 4s 内：defer「换频静默」；日志 `post-hop quiet`；静默期内 ChannelHop 位不 resume；排队点击在静默结束后可先放刀、仍等冷却满再发  
9. transfer 后会话硬断：`Disconnected` 立刻 Fail；`Disconnecting` 短闪不误杀  
10. 图里挂机很久再 F10：**不应**误报「进图冷却」（仅刚进图/刚落地 4s 内）  
11. 注入后第一次点换频：App 写盘后 payload 应有 `request seq=`（勿被首拍收养吞掉）；进图前残留旧 seq 重注仍不应自动 hop

- 不移植枫星 Reload（遇人自动换频见 `encounter`）
- 不新建命名管道
