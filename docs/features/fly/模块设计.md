## 1. 为什么从开环换成旋翼（2026-08-07）

旧实现每 120ms 朝鼠标世界点发一发 `ImpactImpulseToward`（`speedScale=4 / maxSpeed=1600`），
**从不读自己的速度，也没有任何重力配平**。它靠超调硬顶重力——所以鼠标不动时必须每 200ms
「重钉」一次落点（`kHoverRepinMs`）才不往下沉，那个 hack 就是缺配平的补丁。

换成 A 层旋翼后白拿四样：

| 能力 | 旧开环 | 旋翼 |
|---|---|---|
| 重力配平 | 无，靠超调硬顶 | `trim` 按真实间隔预付，**鼠标不动即真悬停**，重钉整段删除 |
| 速度反馈 | 无 | 闭环 `cmd = vt − v` |
| 撞墙预刹 / 位置包线 | **无，能把人直接飞出图** | 有（越界断线的来源之一） |
| 落速闸 / 深度缴械 | 无 | 有 |

**坐标系无需换算**：`ImpactImpulseToward` 内部就是拿 `worldX − apX` 算差值，而旋翼的
setpoint / `QueryFlightState` 用的是同一组 `Ap` —— `ScreenToWorldPoint` 的输出直接可用。

## 2. ★ 旋翼所有权（三方共用一个单例）

旋翼是**单例**：一份 setpoint、一份发射时钟。驱动方却有三个——F5 打怪、自动赶路、F6 手动飞。

**为什么不能靠「把另一个暂停掉」解决**：`simple_combat::Tick` 里 `TickHeliRotor(now)` 刻意放在
`gExternalPause` 判断**之前**，因为 fh-ban 挂着时停一拍旋翼就是掉一段。也就是说旋翼**必须
一直转**，能换的只有 setpoint 的来源。所以要的是**交接**，不是暂停。

| 角色 | Owner | 取得方式 | 理由 |
|---|---|---|---|
| F6 手动飞 | `Owner::Fly` | `Acquire`（**抢占**） | 人按了键就该立刻听人的 |
| F5 打怪 | `Owner::Combat` | `TryAcquire`（仅无主时），**每 tick 调** | 不回抢，避免对拽；F6 一释放立刻接回 |
| 自动赶路 | `Owner::Travel` | 同上 | 同上 |

- 非持有者调 `SetSetpoint` / `Tick` **静默 no-op**，它自己的循环不用改，也不会去拆 fh-ban。
- 自动方**必须每 tick 都 `TryAcquire`**：F6 释放后旋翼变无主，没人接管而 fh-ban 还挂着 = 自由落体。
- `Reset()` 是全局复位（连所有权一起清）。**非持有者不得调用**——`fly.cpp` 的换图钩子先判
  `CurrentOwner() == Owner::Fly` 才 Reset，否则 F6 没武装时也会把正在打怪的 F5 掀翻。

## 3. 产品链路（现行唯一）

```text
面板「飞行」/ F6
  → SetArmed(true)
  → fly_fh_ban::SetArmedBan(true)      // CollisionDetect / Float 拦截 LocalUser，清 CurFh
  → heli::Acquire(Owner::Fly)          // 抢占式接管旋翼

worker（Sleep 8ms，武装期每拍都跑）
  → PollAimFollow()：光标动了 → 主线程 job ScreenToWorldPoint → SetTarget（夹进合法空域）
  → PollLmbHop()  ：左键边沿 → 同上，标 tag=click
  → DriveRotor()  ：SetSetpoint(Fly, {tgt, Cruise/Station}) + Tick(Fly)

旋翼（A 层，内部自控 ~11Hz）
  → 闭环算 cmdV → ImpactSetVelocity → impactNext{Valid,Vx,Vy}
  → WorkUpdateActive → ApplyImpact → Ap.V 更新 + MoveElem Attr=2
```

| 项 | 现行 |
|----|------|
| 驱动 | **heli_rotor 闭环**（A 层） |
| Attr | **`a=2`** |
| 穿层 | **fh-ban**（武装期不重挂台） |
| 无敌 | **要求** `invuln::IsEnabled()`（不偷偷 SetDesired） |
| 目标刷新 | 默认 **16ms**（= 时钟地板，最密）、下限 5ms；真实地板见下 |
| 冲量节奏 | 旋翼自控 ~11Hz，紧急 20ms；**外部不限频** |
| 档位 | 距目标 >140px **或光标在动**用 `Cruise`；近了且停手才 `Station` 收速 |
| 前馈 | `Setpoint::leadV` = 光标世界速度（差分+EMA），停手 500ms 归零 |
| 空域 | `Setpoint::unbounded=1` —— 左右/上方无约束；**只留向下那一面**（见下） |
| 速度倍率 | `flySpeedPct`，与 F5 那份**各存各的** |
| worker | `Sleep(8)`；`IsCongested()` 时**只跳过目标刷新**，旋翼照转 |

### 语义变更（两个旧字段）

- **`flyHopCdMs`**：旧＝发冲量的节奏；现＝**目标点刷新间隔**（多久重算一次 STW，那是主线程
  job，不能每 8ms 做）。冲量节奏已由旋翼接管。
  默认 120→40→**16**（BIN 5c3950 手调到 16 后确认手感到位，且 16 正压在时钟地板上，
  是这套时钟能给到的最密刷新）；下限 40→16→**5**。
  加了前馈之后刷新间隔对跟手的影响已降一个量级——两次刷新之间角色按估出的光标速度继续走。

#### ★ 真实地板是时钟的 15.625ms，不是这个旋钮

**别再拿「刷新不够密」去解释不跟手**——先看这份实测。

BIN 5c3950 + a0ab58 共 104 个 `Fly heli … since=` 样本（两次成功发冲量的间隔），取值只有：

```
0 / 15·16 / 31·32 / 47 / 62·63 / 78·79     ← 全是 15.625 的整数倍，无一中间值
```

刷新闸 `AimReady()` 比的是 `GetTickCount()` 差值，而该进程的定时器分辨率实测 **15.625ms**，
它每 15.6ms 才跳一格；worker 的 `Sleep(8)` 同理实际睡 ~15.6ms。**结论：5 / 10 / 15 / 16
走的是完全相同的代码路径**，把旋钮往下拧不会更跟手。

那为什么还把下限放到 5？为了**不把一个会过期的假设写死**：若进程时钟被提到 1ms
（Unity 或别的进程调 `timeBeginPeriod`），旋钮自动开始咬合，不必改代码。
想主动跑到 5ms 只能自己 `timeBeginPeriod(1)`，那是**进程级副作用**（影响游戏自身计时与功耗），
不该由本功能替用户决定——要做也得是显式开关 + 实测收益。

顺带否掉旧下限的理由（原写「8ms=125 次/秒会排满主泵」）：BIN 5c3950 全程 16ms 刷新，
`aim pump timeout` / `ScreenToWorld fail` / 拥堵均为 **0**。卡的是时钟，不是主泵负载。
- **`flyMode`（路线 A/B）**：对**飞行**已完全失效——冲量路由由 A 层内部的 `ImpactSetVelocity`
  决定，不走 `NockBack` / `SetImpactNext` 分支。字段与 IPC 保留只为面板/存档兼容。

### 为什么 F6 的速度倍率要跟 F5 分开

旧 F6 开环等效约 **1600 px/s**，而旋翼 `Cruise` 基准只有 **620**——直接接过去手感会慢 2.6 倍。
两者对手感的诉求本就不同（手动飞求跟手、自动打怪求稳），共用一个旋钮必有一方别扭，
所以倍率**按 Owner 各存一份**，生效的是当前持有者那一份，交接时自动跟着换。

因此 F6 默认取 **300%（`kFlySpeedPctDefault`）而不是 100%**：1.0X 开箱就比旧版慢一大截，
是手感退步；3X 略高于旧版的 2.6X，留一点余量（手动飞有人盯着，快点比慢点好收）。
F5 那份仍是 100%——它的档位是按打怪实测调出来的，不跟着改。

### 为什么 F6 不受空域约束（产品定位，2026-08-07）

**包线是为「无人盯着的自动打怪」设计的，不是为手动驾驶设计的。** F6 是用户拿鼠标在开，
再套一层围栏就成了跟驾驶员抢方向盘：他指哪儿、机器往回顶哪儿。何况 AABB 只是**可站立面**的
包围盒，从来就不等于合法空域（见 `heli_rotor.h` 的 `kEnvSlackYPx` 长注），拿它当围栏对手动飞
本就结构性过严。所以 F6 发 `sp.unbounded=1`：

| 方向 | F6（手动） | F5 / Travel（自动） | 依据 |
|---|---|---|---|
| 左 / 右 | 放开（无内推、无预刹） | 保留 | 界外是纯空气；c9b8dc 那次掉线是**界外出刀**，F6 不出刀 |
| 上 | 放开（无下沉、无预刹） | 保留 | 上沿之外纯空气，回来没有紧迫性 |
| **下** | **保留**（上拉 + 底侧预刹 + 深度缴械） | 保留 | 四面里**只有这一面会毁掉会话** |

向下为什么对谁都不放：穿出最低台会被引擎判掉图 → 重载/断线，就是 a69130 野猪图那次
「越界重拉」。而且**底侧预刹必须一起留**——位置包线是「越过才报警」的事后判据，
5X 一个周期就能走完整个 `kBailoutPx`，只留位置判据等于没留。

配套：`SetTarget` 不再调 `ClampToAirspace`。早先夹过一版，结果是把目标点钉在包线绊线上，
过冲 1px 就吃满档下压（BIN a0ab58 的「到点→掉落→吸附」循环）。包线既已让位，再夹一次
反而是重新造出那条绊线。

### 为什么必须给前馈（「不跟手」的真因，2026-08-07 · BIN 752824）

倍率调到 3X~5X 后仍报「不跟手」。实测：中位跟随误差 **114px**、p75 194px，而中位意图速度只有
**792**——两档上限（3X 下 1440/1860）**根本没咬住**。所以慢的不是限速，是控制律本身：

纯比例控制跟移动目标必留稳态滞后，`desiredV = Kp·err ⇒ err = V目标/Kp`。Kp=7、光标扫到
800px/s，就恒定落后 114px（与实测中位数一致，不是巧合）。换个视角同样说明问题：从 1860px/s
按 Kp=7 刹停不超调需要 `cap/Kp ≈ 266px` 的减速区，也就是大半个行程都在减速。旧开环之所以「跟手」
正因为它不管距离一律甩 1600px/s——代价是冲过头飞出地图，那是当初换旋翼的原因，不能退回去。

解法是把目标自身速度**前馈**进意图：`desiredV = V目标 + Kp·err`。前馈负责跟上、反馈只补偏差，
稳态滞后归零；且它是开环项，不动闭环极点、不带来振荡。所有钳位（档位限幅、包线内推、撞墙预刹、
可达集）都在下游，安全性一分不减。

- 目标速度由 F6 自己估：连续两次**跟随**刷新差分 + EMA(0.5)，钳 ±2400。
- **点击瞬移不算**（`track=false`）：那是跳变，差分出来是毛刺不是速度。
- **F5 打怪固定留 0**：它的 setpoint 在怪之间跳变，同理。
- 停手判据用「距上次跟随刷新 >500ms」而非「光标是否移动」——后者由屏点死区决定，微抖也算动。

面板位置：**调试 TAB → 飞行调试**，两个倍率并排（F5 那个原在首页「打怪」卡，已移过来），
各带 1X/2X/3X/5X 快捷档。倍率的边界语义（哪些量跟随、哪些绝不跟随）见
[`../simple_combat/模块设计.md`](../simple_combat/模块设计.md) 的「飞行速度倍率」节。

## 4. 交互

1. **面板「飞行」** 或 **F6** → 武装 / 卸武装（`state/fly_armed` 会话态，不持久化）
2. **跟随**：前台 + 无 Ctrl/Shift + 刷新间隔到 → 光标位移 ≥3px 才重算 STW。
   光标不动**不需要**任何重钉——旋翼自己钉住目标。
3. **左键**：armed + 前台 + 无 Ctrl/Shift + LMB 边沿 → 设新目标
4. 失焦 / 按住 Ctrl-Shift / 主泵拥堵：**只停更目标，旋翼继续悬停**。旧实现在这些分支直接
   `return`，等于停发冲量而 fh-ban 还挂着 —— 人就往下掉。
5. 外部暂停（`auto_supply` 补给中）：`Disarm(Fly)` 停发冲量，语义与旧实现「不 hop」一致。
   ⚠️ 此时 fh-ban 仍挂着，角色会持续下坠且接不住地板 —— 这是**改造前就有**的行为，本轮原样保留。
6. 换图 / 重新 PlayReady：清跟踪；**且仅当自己是持有者时** `heli::Reset()`
7. 卸武装：`fh-ban` OFF；`Disarm(Fly)` + `Release(Fly)`，随后 F5/赶路下一拍即可接回

IPC：`PayloadControl_PublishFly` / `core.flyMode` / `core.flyHopCdMs` / `core.flySpeedPct`

## 5. 与 F5 打怪的关系

**同一套 A 层**（`heli_rotor`），差别只在 setpoint 从哪来、以及 fh-ban 记在哪个源上：

| | setpoint 来源 | fh-ban 源 | 旋翼 Owner |
|---|---|---|---|
| F6 手动飞 | 鼠标世界点（`ScreenToWorldPoint`） | `BanSource::Fly` | `Owner::Fly`（抢占） |
| F5 打怪 | 锁定怪的站位点 | `BanSource::CombatImpact` | `Owner::Combat`（仅无主时接管） |
| 自动赶路 | 传送门瞄点 | `BanSource::Travel` | `Owner::Travel`（同上） |

- fh-ban 多源 **OR**，互不踩灭；API `fly_fh_ban::SetSourceArmed`。
- 实测物理（`+Y 向上`、重力每 30ms 步 `-60`、Y 是叠加语义、上升**无**引擎封顶）详见
  [`../simple_combat/模块设计.md`](../simple_combat/模块设计.md) §4.0，动竖直律前必读。
  ⚠️ 曾写在这里的「合速钳在 `[-670,+110]`」是错的，已撤回——那是旋翼自己的限幅，不是引擎特性。
- **别再把开环那套搬回来**（无论 F5 还是 F6）：无配平就得靠超调硬顶重力，且没有包线，
  必掉图。历史依据见本文 §1 与 simple_combat §4.0。

## 6. BIN 验收清单

1. `init drive=heli`；武装：`panel/ipc ARMED drive=heli … fhBan=1 speed=x.xxX`
2. 所有权：武装时应有 `Heli owner combat -> fly`（或 `none -> fly`）；卸武装 `fly -> none`，
   随后 F5 若在跑应立刻出现 `none -> combat`。**不应**看到 fly/combat 反复易主（那是对拽）
3. 跟飞：`Fly heli mode=cruise|station tgt=… ap=… v=… lead=… des=… emg=0`，每秒一行
4. **跟手判据**：扫动光标时 `lead` 应非零且与 `v` 同向同量级；`|tgt-ap|` 的中位数应显著低于
   未加前馈时的 114px。若 `lead` 恒为 0，先查是不是走了 `track=false` 的点击路径
5. **悬停判据**：鼠标不动时 `ap` 的 y 应基本不掉（配平生效）；`lead` 应在 500ms 内归零，
   否则角色会顺着最后一次扫动一直飘；日志里不应再有任何「重钉」
6. **指到图外**：F6 走自由空域（`sp.unbounded=1`），左右与上方**不再有任何回推**，
   `tgt` 不再被钳、`emg` 在这三个方向恒为 0，角色应老实停在光标处。
   唯一还会顶回来的是**向下穿出最低台**（该图 `T − 48` 以下）：那会出现 `emg=1` 上拉，
   再深就 `bail deep` 缴械——这一面对谁都不放，理由见下节
5. MpFlush 空中包：`a=2!` / `tel>0`；关注 `maxErr` / `over` / 软踢时刻
6. `emg=1` 只应出现在真贴边时；若巡航中段频繁 `emg=1`，八成是 setpoint 没夹进合法空域
7. 卸 F6 后不应再出现 `Fly heli` 行
