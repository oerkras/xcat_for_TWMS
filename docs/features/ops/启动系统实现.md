## 1. 这个系统要解决什么

把经典版客户端 `Maplestory_Classic.exe` 用 **与官网「启动游戏」等价的路径** 拉起来：

- 会话票来自 Gamania Galaxy / beanfun OpenID，**不是** Nexon `/sid:`。
- 官网流程：`OTT` → `POST /api/Login/GetOneTimeWebInfo` → `NGM.LaunchGameOnlyPassArgs(...)`。
- 我们采用同一套 **NGM deep-link 的 `-passarg:`**，把换票四元组透传给 NGM，由 NGM 启动客户端。

对照枫星（老项目）时务必分清：

| | 枫星 / MSW | 经典版 / MSC |
|---|---|---|
| 进程 | `msw.exe` | `Maplestory_Classic.exe` |
| 鉴权源 | Nexon NGM 登录 → cmdline `/sid:` | Galaxy OTT → `userSessionToken` 等 |
| passarg | `/runmode /gameid /publishid /gamename /publishname` | `userObjectID userSessionToken gid galaxy_GameId` |
| `-game:` | 固定 `106603` | API 字段 `game`（实机钉死前勿硬编码） |
| 造不出来的东西 | `/sid:` | `userSessionToken` / 有效 `OTT` |

官网启动页与脚本真源：

- [maplestoryclassic.beanfun.com/Main](https://maplestoryclassic.beanfun.com/Main)
- `/web/js/components/float-btns.js`（`gamePlay` / `ottLoginApi` / `NGM.LaunchGameOnlyPassArgs`）
- `/web/js/api.js` → `GetOneTimeWebInfo`
- `https://platform.nexon.com/NGM/JS/npf_ngm.js`

## 3. 关键数据结构（`launcher/msc_launch.h`）

```cpp
enum class Stage {
    Init,
    FindingNgm,
    LaunchingGame,
    WaitingForGame,
    Done,
    Failed,
    BlockedNeedsTicket,  // 缺 OTT/换票结果
};

enum class NgmMode {
    Launch,   // 官网 LaunchGameOnlyPassArgs 默认
    Restore,  // 枫星现行；经典版待实机验证
};

struct GalaxyTicket {
    std::wstring userObjectId;      // ottRes.data.userObjectID
    std::wstring userSessionToken;  // ottRes.data.userSessionToken（短命，勿落盘明文）
    std::wstring gid;               // ottRes.data.gid
    std::wstring galaxyGameId;      // ottRes.data.galaxy_GameId
    std::wstring ngmGameId;         // ottRes.data.game → -game:'...'
};

struct Options {
    GalaxyTicket ticket;
    NgmMode      mode = NgmMode::Launch;
    std::wstring gameExeName = L"Maplestory_Classic.exe";
    int          waitGameSec = 90;
    bool         dryRunDeepLinkOnly = false;  // 只生成 deep-link 摘要
    bool         attachExistingClassic = false;  // 策略 B：已有经典版则跳过 NGM 直接接管
    int          attachMaxAgeSec = 1800;         // 接管年龄窗；更老视为上一局残留（0=不限）
};

struct Progress {
    Stage         stage;
    std::string   message;
    unsigned long gamePid;
};

struct Result {
    bool          ok;
    Stage         finalStage;
    std::string   errorMessage;
    unsigned long gamePid;
    std::string   deepLinkSummary;  // 仅脱敏摘要；禁止回传明文 deep-link
};
```

`TicketLooksUsable()`：五段非空，且拒绝 `'` / `"` / 空白 / 控制符 / `\`（防 `-passarg:'...'` 截断）。

### 接管已有经典版（`attachExistingClassic`）的判定（2026-08-05 收紧）

`FindExistingClassicPid` 回传 `ticketMatched` 与 `outUnmatched`，`Run` 据此三分：

| 情形 | 处置 |
|---|---|
| cmdline 四元组匹配本票 | 确定是本次登录的实例 → 接管 |
| 无匹配，但年龄窗内只有 1 个候选 | 官网自启的常见情形 → 按既有策略接管 |
| 无匹配，且年龄窗内有 ≥2 个候选 | **无从判定哪个属于本票 → 拒绝猜测**，改走 NGM 正常拉起 |

年龄窗 `attachMaxAgeSec`（默认 30 分钟，含 2s 时钟偏差）对标 `gamapass_cdp_login` 的
`sessionNotBefore`：更老的实例按上一局残留处理，不接管。

**修的是什么**：此前 `Run` 既不传年龄窗，`matched` 也只用于日志文案、不参与决策——多开或有残留客户端时
会静默接管「最新的那个」，等于注入到别的账号，而刚换到票的账号根本没被拉起。**全程不结束任何进程**，
只是不接管；也不触碰任何登录态。

`GalaxyTicket` 字段与官网 `float-btns.js` 对齐：

| 字段 | 官网 JSON | 用途 |
|---|---|---|
| `userObjectId` | `data.userObjectID` | passarg 第 1 段；客户端 `Galaxy_UserObjectID` |
| `userSessionToken` | `data.userSessionToken` | passarg 第 2 段；`Galaxy_UserSessionToken` |
| `gid` | `data.gid` | passarg 第 3 段 |
| `galaxyGameId` | `data.galaxy_GameId` | passarg 第 4 段 |
| `ngmGameId` | `data.game` | NGM `-game:'...'`（**不是**四元组里的 galaxyGameId） |

非法或缺失 → `BlockedNeedsTicket`（对应老项目「请确认 NGM 已登录」）。

## 4. Run() 流水线（`launcher/msc_launch.cpp`）

```
0. 参数校验           TicketLooksUsable（非空+字符白名单）；否则 BlockedNeedsTicket
1. 找 NGM             ProgramData\Nexon\NGM\NGM64.exe 等候选 + ngm:// 注册表
2. 生成 deep-link     栈上 BuildNgmDeepLink；Result 只留 FormatDeepLinkForLog 摘要
3. dry-run？（可选）   dryRunDeepLinkOnly → Done（不拉进程）
4. 快照 PID           CollectPidsByExeName(gameExeName) → before 集合
5. EnsureNgmRunning   冷机先拉 NGM；失败仍继续 deep-link
6. 启动游戏           ShellExecute(ngm://) → 失败则 CreateProcess(NGM64, deep-link)
                      失败路径带 Shell/CreateProcess 错误码
7. 等待验票           WaitForClassicWithTicket：新 PID ∧ cmdline 四元组 == ticket
8. Done               返回 gamePid + deepLinkSummary + cmdLineSummary
                      （未做）登录 UI/ACS 门闩 / 注入
```

### 4.1 与老项目流水线对照

| 步骤 | 枫星 `launcher_run.cpp` | 经典版骨架 |
|---|---|---|
| 找游戏 | 找 `msw.exe` 安装路径 | 暂不强制；交给 NGM |
| 联网配置 | publishId HTTPS 刷新 | OTT / GetOneTimeWebInfo（**未接**；票由外部填入） |
| 已在跑检测 | cmdline `/sid:` + gameid/publishid 匹配 | 拉起前 PID 快照；**不**把旧进程当成功 |
| 启动 | EnsureNgm → deep-link → .url → 裸 ngm | EnsureNgm → deep-link → CreateProcess（**无** .url/裸 ngm） |
| 鉴权就绪 | `WaitForMswWithAuth`（等 `/sid:`） | `WaitForClassicWithTicket`（等位置参数四元组） |
| 切服 | kill+restart 改 `/publishid:` | N/A（无 UGC 世界切服） |
| 注入 | Classic LoadLibraryW | **已产品化**：见 [`GAMA_PASS与注入闭环.md`](GAMA_PASS与注入闭环.md) §4 |

### 4.2 注入方式（已实施 · 摘要）

对齐老项目 2026-06 实机结论与本仓 GRAP 文档：**默认只走 Classic `LoadLibraryW`**。

```text
VirtualAllocEx(remote dll path)
→ WriteProcessMemory(path)（失败则 NtMapViewOfSection）
→ CreateRemoteThread(kernel32!LoadLibraryW)
→ 枚举确认 LDR 中有 xcat.dll
```

经典版编排（`InjectIntoClassic`）：等 `GameAssembly.dll` → settle **3s** → 注入；已加载则跳过。  
进程内再做 ≈15s native settle + MainPump（见闭环文档 §4.3）。

- **禁止**把 manual-map / stealth / spawn 当作默认路径写进产品。
- 完整无人值守 / 守护 / 与枫星差异 → [`GAMA_PASS与注入闭环.md`](GAMA_PASS与注入闭环.md)。
- 安全定调 → [`../security/GRAP与枫星对齐.md`](../security/GRAP与枫星对齐.md)。

### 4.3 敏感信息铁律

- `userSessionToken` / 完整 `-passarg` / 完整 deep-link：**禁止**写入 `Result`、日志或仓库。
- `Result.deepLinkSummary` 与进度回调只允许 `FormatDeepLinkForLog`（`-passarg:'***'`）。
- deep-link 明文仅存在于 `Run` 栈上临时变量，函数返回后不再对外可见。
- OTT 与 SessionToken 均短命；过期必须重新走 Galaxy，禁止当长期免登凭证缓存。

## 5. NGM deep-link 格式

官网等价（`NGM.LaunchGameOnlyPassArgs` → `GenerateArgument` + `GenerateURI`）：

```
ngm://launch/ -mode:launch -game:'<data.game>' -passarg:'<userObjectID> <userSessionToken> <gid> <galaxy_GameId>' -architectureplatform:'none' -timestamp:<ms>
```

骨架实现：`BuildNgmPassarg` + `BuildNgmDeepLink`。

说明：

- `-mode:launch`：与官网 JS 默认一致。`-mode:restore` 在枚举中预留（枫星现行），**经典版是否更稳需实机对比**，不得凭枫星经验直接改默认。
- `-game:'…'`：来自换票 API 的 `game` 字段；在实机钉死常量前保持运行时传入。
- `-passarg:`：四段空格分隔，交给 NGM；**NGM 再拆成游戏进程位置参数**（见 §5.2）。
- 系统协议注册（本机实锤）：`HKLM\Software\Classes\ngm\Shell\Open\Command` → `"C:\ProgramData\Nexon\NGM\NGM64.exe" "%1"`。

### 5.1 枫星 deep-link（对照，勿混用）

```
ngm://launch/ -mode:restore -game:106603 -passarg:'/runmode:play /gameid:... /publishid:... /gamename:... /publishname:...'
```

### 5.2 游戏进程 cmdline 实锤（2026-07-30）

本机 `Maplestory_Classic.exe` 经 `NtQueryInformationProcess(ProcessCommandLineInformation=60)` + `PROCESS_QUERY_LIMITED_INFORMATION` 读到：

```text
"G:\Games\maplestory_classic\Maplestory_Classic.exe" <userObjectID> <userSessionToken> <gid> <galaxy_GameId>
```

采证形态（token 打码）：

```text
"…\Maplestory_Classic.exe" 4662771 sess5d*** 2373 944
```

| argv | 语义 |
|---|---|
| `[0]` | exe 路径（常带引号） |
| `[1]` | `userObjectID` |
| `[2]` | `userSessionToken`（日志只留前缀） |
| `[3]` | `gid` |
| `[4]` | `galaxy_GameId`（与 Galaxy OTT 中的 `944` 一致） |

要点：

- **不是** `-passarg:'…'` 留在游戏 cmdline；也**不是**枫星 `/sid:` / `/gameid:`。
- PEB `ReadProcessMemory` 曾 `ERROR_ACCESS_DENIED`；读 cmdline 用 **class 60**，不要只抄枫星 PEB 路径。
- 就绪门闩：`WaitForClassicWithTicket` = 新 PID ∧ 四段全等匹配。
- 脱敏：`FormatCmdLineForLog` → `"exe" uid token*** gid galaxyId`。

## 6. 换票链路（官网 · 本骨架的票源）

开游戏需要的是 `GalaxyTicket`。换票主路径：**GAMA PASS CDP** 或 **HK HTTP**；**无 WebView2**。

### 6.1 HTTP 模拟登录（gamania HK）

```
StartOneClick（AuthStrategy=HTTP）
→ GET galaxy…/login/mstc → sessionOtt（/login/init/mstc/OTT:…，仅供 result POST）
→ GET bfweb.hk.beanfun.com/.../bflogin/default.aspx?service=610076_T0&url=…/login/result/mstc/ghk
→ login.hk.beanfun.com/login/id-pass_form_*.aspx?otp1=…
→ POST 账密（记住帐号）→ AuthKey / WebToken
→ GET Galaxy result?WebToken=（可选抽 CSRF）
→ POST result/mstc/ghk?WebToken=  body {ott:sessionOtt, fromSelf:true[, _token]}
   → Results.Ott = ticketOtt（OTT:944:Login:…）
→ POST /api/Login/GetOneTimeWebInfo { OTT=ticketOtt }
→ GalaxyTicket → NGM.LaunchGameOnlyPassArgs / Run() + 注入
```

日志区分：`sessionOtt=`（Galaxy init）与 `ticketOtt=`（换票）；POST 失败会打 `status / RCode / Message / body_snip`。

边界：

- 遇 **驗證碼 / reCAPTCHA / 雙重驗證**：HTTP **明确失败**（不打码）；按「验证码UI」开系统浏览器或仅提示。
- 换票忙碌看门狗约 **5 分钟**。
- 落点：`launcher/http_client.*`、`http_beanfun_login.*`；配置：`bin/auth_strategy.txt`、`bin/captcha_ui.txt`（与 `account.txt` 同级）。

### 6.1.1 验证码验收清单（人工）

| 步骤 | 期望 |
|---|---|
| 干净账号一键 | 日志 `sessionOtt` → `ticketOtt` → `HTTP 换票成功` |
| 触发验证码账号 | 状态栏「需要网页验证」+ 通知；默认开官网浏览器 |
| 验证码UI=不开浏览器 | 仅提示，不自动开浏览器 |

### 6.2 取票策略（启动页）

| 策略 | 行为 |
|---|---|
| `GAMA PASS自动登录` | CDP 点选；无人值守主路径；见 [`GAMA_PASS与注入闭环.md`](GAMA_PASS与注入闭环.md) |
| `HTTP`（HK） | 账密 HTTP 换票；历史 `http_only` / `webview_only` 读盘归一为此 |

### 6.3 验证码 UI（启动页 · HK）

| 模式 | 行为 |
|---|---|
| `开浏览器`（默认） | 验证码时打开官网 |
| `不开浏览器` | 仅提示，自行处理 |

## 10. 故障排查

| 现象 | 处理 |
|---|---|
| HTTP 登录遇验证码 | 文案明确失败；`HTTP优先`+有 Runtime → 自动 WebView；否则装 Runtime 或改策略 |
| 未找到 NGM | 确认 `C:\ProgramData\Nexon\NGM\NGM64.exe` 或 `ngm://` 注册表 |
| ShellExecute 失败 | 看 CreateProcess 回退是否成功；查协议处理程序 |
| 等待新游戏超时 | 票过期、未装经典版、NGM 未绑定该 `-game:`，或仅有拉起前旧进程 |
| 把旧登录页当成功 | 已用 PID 快照防护；若仍误判查是否 PID 复用（极少） |
| 新进程在但仍停登录页 | passarg 未吃到或票无效；补 cmdline / WebView 状态门闩（TODO） |
| Ticket 被拒（非法字符） | 检查字段是否含引号/空白；以 API 原始值为准勿手改 |
| 日志里出现明文 token | **缺陷**：改走 `FormatDeepLinkForLog`，轮转并删除含密日志 |
| 误用枫星 `/gameid:/publishid:` | 经典版不会认；必须用 Galaxy 四元组 |
