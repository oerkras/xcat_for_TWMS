## 1. 证据边界

| 等级 | 含义 |
|---|---|
| **实锤** | dump 符号 + 当前 IDB 解出 id 与 thunk 一致（种子实读）+ 代码 xref |
| **强推断** | 命名 + call 序 + BIN 时空对得上，比较式未完全去 CFF |
| **未钉** | 运行时现货、单位、本轮 18 次 205 的具体族、服端是否再算一遍 |

**禁止**：把旧笔记 RVA 当成本 IDB 地址。`0x1774C90` 曾被当成 926，当前 dump 解出来是 **856**（FastAccess）。GetInt 公共 helper 是 `sub_7FFD61F08680`（RVA `0x16D8680`，约 5634 调用方）：`mov ecx, IMM` → `xor`/`add ecx, cs:seed` → `call helper`。

CFF 函数的 Hex-Rays 伪代码几乎只有跳表初始化，**以 `insn_query` / 实读种子为准**。`jmp cs:off_*` 的 IDA 静态目标经常指到 epilogue，不可当成「GetInt 之后立刻 return」。

### 4.2 已还原的算术（`6244D430` · 种子实读）

函数内大量 `cmp eax, edx` 解出来是 **0**，是 il2cpp `klass[+0xE4]` 初始化门，**不是阈值**。

寄件函数里的算术（不要当拉怪阈值）：

```text
0x6244E592  rdx = 0xAC49920354A5ADDA + [0x7FFD67114F18]
            → rdx = 100000000 (0x5F5E100)     ; 实锤
            cmp rax, rdx / jge …
0x6244E5BE  cvtsi2sd xmm0, rax
0x6244E5C9  mulsd xmm0, [0x7FFD66104F98]
            → 乘数 = 0.06                     ; 实锤（IEEE double）
0x6244E5D7  cvttsd2si rcx, xmm0
```

**强推断（单位未钉）**：`0.06 ≈ 1/16.67`，像「毫秒 × 0.06 ≈ 60fps 帧数」；`100000000` 像 .NET `TimeSpan` 10 秒的 tick（10×10⁷）或溢出哨兵。不能写成「阈值 = 100000000 px」。

随后还有 `GetInt` / `object_new` / `60F87610`。在「这是寄件 UI」前提下，**0.06 与 1e8 更像金币/税率/TimeSpan，不要再当拉怪 px 阈值**。GetInt(927) 出现在寄件函数里仍然奇怪（CFF 邻接或寄件也读反作弊表）——**战斗路径未使用**已由 v1 BIN 钉死。

### 10.10 EndUpdateActive → Flush → Encode → 出站（2026-08-23）

EUA 本体无跳表噪声、可以按指令走完（CFF 只用来藏空检查）：

```
mov  rcx, [this+0x78]          ; MovePath
xor  edx, edx
call IsTimeForFlush(false)
jz   ret                       ; 未到点：不 new 包、不 Flush、不 Send
movzx ecx, word_670D2CF0       ; IDA get_word = 0x15A9

mov  rdx, packet
xor  r8d, r8d
```

**出站号 0xC4 ≠ 断线理由 205 ≠ CMS `ClientPacket.MobMove=205`。** 种子用 IDA `ida_bytes.get_word` 实读，不是 MCP `get_int`。旁证：另一条 Flush 调用方 `61A32000` 用同一工厂，种子 `word_670D35FC xor 0x6831` → **47**，CMS `ClientPacket.UserMove=47`，解码方法对。因此 **196 就是 TWMS 这条怪 Flush 通道的包号**；CMS 同槽 196 是 `QuickslotKeyMappedModified`，表已重排，不要拿 CMS 枚举硬贴。枫星 kick_sniff 的「MobMove=207（CMS+2）」是另一产品线，对本仓无效。

Flush（7.8KB CFF）**只跟一层 callee**：唯一业务编码入口是 `Encode`。其余是 throw / nullsub / il2cpp。禁止工线 `invoke Flush`、禁止对 Flush 下 E9（角色侧协议文档已写；采证钩默认关）。

Encode 也不摊 CFF。点到字段即可：CMS `MoveElem` 布局 `Attr@+0x10 / X@+0x12 / Y@+0x14 / Vx@+0x16 / Vy@+0x18 / MoveAction@+0x1A / Fh@+0x1C / FhFallStart@+0x1E / Elapse@+0x20`。Encode 在 `Encode2` 前实读：

| 读地址 | CMS 字段 |
|---|---|
| `[MovePath+0x10]` | MovePath 头 `_x`（首个 `Encode2`，`movzx edx, [rdi+10h]`） |
| `[MovePath+0x12]` | MovePath 头 `_y` |
| `[elem+0x12]` | `X` |
| `[elem+0x14]` | `Y` |
| `[elem+0x16]` | `Vx` |
| `[elem+0x1C]` | `Fh` |

`Encode1(byte)` 打 2 次（Attr / Stat 一类）。Inspect 写下的 **Teleport=4** 格和 `MakeContinuousMovePath` 的 Normal/FallDown/Wings 格走同一 `List<MoveElem>`，Flush 到点就整表编码进 `0xC4` 包。服端拿包里的新坐标自量位移 → 族 A → 断线 **205**。

**与 `0xF5D0EA` 并列、不是同一函数。** `F5D0EA` 内联在 `SendMobPrevPosHack` 大 CFF `sub_7FFD61789D50`（RVA `0xF59D50`）：`disp=√(dx²+dy²)` vs `|e|+10`，正常包 `object_new`+ctor+填 `[r13+10/14/28/30]`+send。WUA **不 call** 它。翻 `cmovz` 强迫走正常包仍 205（已证伪）。Inspect 写入的 Teleport 格进网走的是 **本条 EUA/Flush**。

Flush 的 code xref（除 EUA）：`6176E060`（大）、`617D0850`（opcode 解码 217）、`61A293C0`（182）、`61A2E190`（190）、`61A32000`（**47 UserMove**）。后三条是角色/召唤/宠物移动家族，不是怪 205 发送源。

**`IsTimeForFlush` 窗口已钉（2026-08-23）**：MovePath `.cctor`（`0x11C4910`）写静态 `GatherTimeShort/Long`。种子 IDA `get_dword` 实读：

| 槽 | 指令 | 种子 | 值 |
|---|---|---|---|
| `[static+0]` Short | `0x33621F2A + dword_670D28F0(0xCC9DE2CA)` | → **500** |
| `[static+4]` Long | `0x2FB0237C + dword_670D28F4(0xD04FE06C)` | → **1000** |

### 10.11 Teleport=4 的 wire（2026-08-23 · Decode 跳表）

Encode 本体仍是 CFF，**镜像 `Decode`（`0x11C0890`）带 IDA 已恢复的 23 路 `switch (Attr)`**（`cmp eax, 16h` / `jpt_7FFD619F0DF1`）。同一 `MovePath` 类，Encode 必须吐 Decode 能吃的布局。

包头（在循环之前）：`Decode2 → MovePath._x@+0x10`，`Decode2 → _y@+0x12`，`Decode1 → count`。

格循环：`Decode1 → Elem.Attr@+0x10`，再按 Attr 分叉，**所有非 10 的分支最后都汇合** `Decode1 → MoveAction@+0x1A`、`Decode2 → Elapse@+0x20`。

| Attr（CMS `MovePathType`） | 跳表落点 | 本格 payload（Attr 字节之后、MA/El 之前） |
|---|---|---|
| **0 / 5 / 15 / 17** Normal · HangOnBack · FallDown · Wings | `619F0EBA` | **绝对** `X Y Vx Vy Fh`（各 Decode2）。仅 Attr==15 再 Decode2 `FhFallStart@+0x1E`（`0x98E307FF+0x671CF810=15`） |
| **1 / 2 / 6 / 12 / 13 / 16 / 18 / 19 / 22** Jump · Impact · … | `619F0DF3` | **相对**：X/Y 拷包头 `_x/_y`；Fh 种子解成 **0**；再 Decode2 `Vx Vy` |
| **3 / 4 / 7 / 8 / 9 / 11** Immediate · **Teleport** · Assaulter · Assassination · Rush · SitDown | `619F0E50` | **绝对 `X Y Fh`，不写 Vx/Vy**。解码后 `Vx=0`（`word_670D2834 xor 0x278A`）、`Vy=0`（`word_670D2838 + 0xFFFFCF33`） |
| 10 StatChange | `619F1046` | Decode1 `Stat@+0x22`；Fh 种子清 0 |
| 14 StartFalldown | `619F0F63` | X/Y 拷包头；再 Decode2 `Vx Vy FhFallStart` |
| 20 / 21 CombatStep · AranAdjust | `619F0FD0` | 无额外 short，直接 MA/El |

**Teleport=4 一格 wire = `attr(1) + x(2) + y(2) + fh(2) + ma(1) + el(2)` = 10B。X/Y 是绝对 short，原样进包。**

Inspect 出盒 helper `619F4FF0`：把 `Ap` 截成 int 当 x/y/vx/vy，**tElapse 种子 `0x45E4E0C1 xor dword_670D2910` = 0**（该 dword 现值就等于 imm，xor 为 0）。所以 Teleport 格 **Elapse=0**。Inspect 写的 Vx=±1 **不会出现在这条 wire 上**——Decode 侧强制 0；±1 只影响后面 `MakeContinuousMovePath` 那格 Normal（走 0/5/15/17 的 14B 绝对布局，与角色 `send.log` Attr0 一致）。

对 205：服端看到的出盒跳是 **Teleport 格里的绝对 (X,Y) 相对上一格/上包终点**，不是 `v·dt`，也不是帧夹速本身。帧夹必须真改写进 Teleport 的 X/Y，否则 500ms 窗口里照样是大 hop。

**仍未拆、实现才会用到**：一包里「Teleport(el=0) + 随后 Normal」服端量哪一段（客户端无阈值；Flush 采证钩对 BIN）。

**不需要为 205 再拆**：Flush 7.8KB CFF 本体、Send 的 CMS 会话类名、opcode 工厂再混淆、926–941 / 408 / 435、`F5D0EA` prevpos。

## 11. 对吸怪实现的含义（不本轮改 gather 夹速）

- **不要**再指望 prevpos / 充 `e` / 翻 `cmovz`。
- **不要**再把 `6244D430` 当拉怪 Kick 去堵；那是包裹 UI。
- 降 205 仍只能让服端量不到大位移：策略 A + 真把逐帧 AP 跳压到门限内（注意 `disp` 是已发生量，hop 950 / 策略 B 瞬移都会破）、软重连复位 spawn 闸、人或落点去怪。
- `InspectUpdateActive` 已在 gather 里钩，不要再 abs-jmp。Inspect **不读** 926–941 / 408 / 525 / 435，钩它挡不了族 A。
- Inspect/WUA 出盒时会 **Append Teleport 格并清 `m_pTarget`**；二次差之后还会 **夹 Ap.X、Vx=±1、Vy=0、`SetInput(±1,0)`、按 Foothold 改 Page/ZMass、`MakeContinuousMovePath(tElapse)`**。这些经 **§10.10 `EndUpdateActive` → opcode `0xC4` Flush** 进服端自量。Teleport 格 wire 是 **绝对 X/Y/Fh、Vx/Vy 不上线、Elapse=0**（§10.11）；帧夹必须改到这格的 X/Y 才算数。
- **不要**工线 invoke Flush，**不要**对 `0x11BC0D0` 下 E9。采证钩仅只读、默认关。
- `617409A0(r14, 0)` 在 Inspect 里经常因 `r14==0` 被跳过；就算走到也是 Sprite MonoBehaviour，不是 Kick。
- Inspect/WUA **一层 callee 已穷尽**（§10.9）：剩下的是 il2cpp cctor、Singleton、按 id 取显示对象、踏板几何查询。没有第二条 205 发送路径藏在 HomeMass / GetFootholdUnderneath 里面。
- 怪移动出站号是 **`0xC4`（196）**，断线理由是 **205**，CMS `MobMove` 枚举是 **205**：三个数碰巧撞号/近号，不要混用。
