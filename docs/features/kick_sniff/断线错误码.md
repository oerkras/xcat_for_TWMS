# kick_sniff · 断线 / pendingError 捕获（Classic TWMS）

> **状态**：联调中（数据面轮询 · **无 INLINE HOOK**）  
> **源码**：`x/features/kick_sniff/`  
> **挂载**：`xcat.dll` DllMain → `kick_sniff::Init` + `StartWorker`；fly `AbortSession` → `DumpNow`  
> **日志**：开发机 `Dumps/runtime/kick.log`；否则模块旁 `logs/kick.log`  
> **证据源（偏移真源）**：`Dumps/runtime/out/dump.cs` TypeDef **13772 / 13797**（TW 哈希类）  
> **对照（易误导）**：`Dumps/cms_cw/dump.cs` 的 `NetworkManager` / `Session` —— **字段尾部与 TW 不一致，禁止直接抄偏移**

## 0. 一句话

抓踢线原因 = 读 **TW** `SessionTcpLayer → Session` 的 **`SessionState@0x60` 边沿** + RING/`verdict`，辅看 `_pendingErrorCode@0x40`；**不要用 CMS Session 的 `List@0x50 / State@0x58`**。  
`ABORT binding lost` ≠ 已证明服务端踢；必须以 `kick.log` 的 `STATE` / RING 为准。  
**`pendingError=205` 几乎总是空闲哨兵，不是踢因**（见 §3）。

**勿混**：`m_bFloatHackCheckNeed` / `m_bABHackCheckNeed` / `ClientHacksType` 是怪仿真与宏举报链，**不是**玩家 UserMove 校验器——见 [`../security/客户端Hack标志与服端推断.md`](../security/客户端Hack标志与服端推断.md)。

## 3. pendingError 语义（2026-08-06 IDA 实锤）

### 3.1 `+0x40` 写入值（TW 运行时 dump · imagebase `0x7FF848C80000`）

`Session.ConsumeErrorCode`（RVA `0x1CC7910`）与各构造/拆线写点，解混淆后 **只写出 204 或 205**：

| 站点（示例） | 算式 | 写入 |
|---|---|---|
| 构造 / Connect 初始化 | `IMM + seed` | **205** |
| `ConsumeErrorCode` 清场 | `dword_…D0CC − 500432935` | **205** |
| 拆线路径两处 | `IMM + seed` / `IMM ^ seed` | **204** |

→ 实机 `kick.log` 全程 `pendingError=205` = **空闲 / 已 Consume 哨兵**，**不是**踢线原因码。  
→ **不要**把 `205` 当成 CMS `ServerPacket.SummonedEnterField`（那是 **opcode** hint，与 `pendingError` 同名不同槽）。

### 3.2 与 `HackingAutoBlock` 的关系（证伪）

CMS 有 `HackingAutoBlock.Move=22` / `Position=24` 等枚举；`kick_sniff.cpp` 仍可把数字映成名字作 **日志 hint**。

但 TW 客户端：

| 项 | 结论 |
|---|---|
| `Session+0x40` 是否写出 22/24 | **否**（全库写点解出仅 204/205） |
| dump 是否有以 `HackingAutoBlock` 为参数的方法 | **无** |
| 本仓全部 `kick.log*` | **从未**出现 `pendingError=22` 或 `24` |

位移 / 飞天类踢的客户端可见路径是：**服端掐 TCP → `CallbackRecv` 写 `SessionState=Disconnected` → a480 本地拆线 → `Nm.CloseSession`**（§4.2）；AutoBlock 名若存在，更可能落在 **通知类包 payload**（未在 TW 实机解出 type=22/24），**不是** `pendingError`。

S→C opcode **提示**（数值表与 CMS 可能同序，**需实机 RING 验证**；与 `pendingError` 无关）：

| op | hint |
|---|---|
| 261 | UserNoticeMsg |
| 269 | ReLoginKickNotice |
| 408 | Warn |
| 143 | SystemBlockAlert |
| 432 | ForceDisconnect?（`OpRecv_01B0`；飞天 BIN 常 **无**） |

## 4. 实现约束（GRAP / 解析）

1. **数据面为主**：轮询 Session 字段；**禁止** Dispatch / Send / Disconnect 的 E9 / `.text` patch。  
2. **CALL_EDGE / SEND_PROBE（诊断 · 默认关）**：  
   - `KICK_CALL_EDGE=1` → **MethodInfo 换针**（`via=MI`）：改元数据堆指针，不改 `.text`。  
   - `KICK_HWBP=1` → **HWBP**（`via=HWBP` / `via=HWBP_WRITE`）：  
     - DR0 执行：`a480.TryLocalDisconnect`（`0xDC7E70`）— 抓 MethodInfo 调用方 `rsp[0]`  
     - DR1 执行：`a480.Update` 内 `call a480`（`0xDD46B8`）— Update 直调路径  
     - DR2 写断：动态盯住当前 `Session*+0x60`（`SessionState`）；仅 extra=0/1 时打栈 + `rip`  
     - DR3 执行：`Nm.CloseSession` — 拆线对照  
     a480 命中附带 `flag+0x298` / `timer+0x29C`。全线程每 2s 刷新 DR。**不改** `.text`。  
   - `KICK_SEND=1` → SendPacket DR → `send.log`（与上独立；`KICK_HWBP=1` 占满 DR 时 Send 会让位）。  
     **等价开关（推荐）**：把空文件 `send_probe.on` 放在 `kick.log` 同目录或 `xcat.dll` 同目录即武装，删文件即关。
     环境变量要求整条链（xcat → 启动器 → 客户端）在设好之后全部重启才继承得到，排查现场很容易踩空；
     标记文件重进游戏即生效。武装成功时 `kick.log` 会打 `via=marker` / `via=KICK_SEND`，未武装则打出
     实际探过的两个路径，便于确认文件有没有放对地方。
   - `galaxy_token_probe.on` / `GALAXY_TOKEN_PROBE=1` → 连上/断线边沿在 Unity 主线程只读
     `PlayerPrefs` 的 `Galaxy_UserObjectID` / `Galaxy_UserSessionToken` / `Galaxy_ExpireTime` /
     `Galaxy_UniqueDevice`，写 `galaxy_token.log`，并在 `kick.log` 留一行摘要。
     **不写完整 token**（只 `len` + 前缀）；默认关。用于核对软重进前票是否还在。
   - 首页「软重连试连」/ `soft_login_probe.on` / `SOFT_LOGIN_PROBE=1` → 断线后 settle，
     再 hold 内等 SceneLogin ConnectLogin（RVA `0xC039D0`；进图后常暂时 `sl_null`，约 20s
     内重试；**已 Connected+世界/频道 UI 则跳过 ConnectLogin**；泵调用 **High**）→
     关踢线弹窗（**绝不点「確認」/OnClickYes/OnClickBtOk**——防踢登录；走
     `UIUtilDialog.CloseDialog` / `UIDialog.Close`；**只扫 Util/Ex + Notice 白名单，
     永不 FindAll(UIDialog 基类)**——防误卸 UIMiniMap 等 HUD；进图后 skip post-dismiss）→
     `auto_enter::RequestRestart("soft_login")`（**softFast**；选角 settle **80ms**；
     见 [`../soft_login/模块设计.md`](../soft_login/模块设计.md) /
     [`../auto_enter/模块设计.md`](../auto_enter/模块设计.md) §10）重跑选区选角；
     `softLoginHold=1` 且进程仍活时 **挡一切** watchdog 干净重拉。
     **成功标准 = pump 上 `IsPlayReady`**（吞 `disconnectSeq`）。
     失败可恢复项先 **soft cycle 最多 5 轮**；单轮内仅 **!inMap** 时 Done 再启最多 **3** 次
     （已回图禁止再启；见 soft_login E216）。
     用尽后 / 停机 → `RESULT fail` 放开 hold → 守护干净重拉。
     过程发 NOTIFY（`soft-login-try` / `soft-login-ok` / `soft-login-fail`）。
     **同一勾选同时武装** Galaxy_* 只读采证（`galaxy_token.log`，仅 len+前缀）。
     默认关。读盘**只认** `softLoginProbe`。
     仅采证：`galaxy_token_probe.on` / `GALAXY_TOKEN_PROBE=1`（或 ini 里单独
     `galaxyTokenProbe=1` 且 `softLoginProbe=0`）。
   - **抓哪一头**：`KICK_SEND_DUMP` 默认 `47,50,51,52,53`，配额 `4000/op`。
     `47=UserMove` 是服端位移校验的真入口（见 [`../protocol/移动协议.md`](../protocol/移动协议.md)），排查
     「被判位移外挂」时是主证据，故列首位。配额是**从会话开头往下扣**的，所以它决定抓到哪一头——
     早期的 `24/op` 只覆盖开局约 12 秒，对「几分钟后掉线」这类问题恰好抓错了那一头。
     `207(MobMove)` 服务的是另一条已结案问题，怪多时速率高会淹掉 `send.log`，默认不再抓。  
   MethodInfo 路径若再 `call` 原入口，HWBP 见返回址在 `xcat.dll` 会跳过，避免双记。  
   `Session.Close` / `CloseSocket` 执行断已让位给上述 a480 分叉探针。  
   **守护模式不依赖上述探针**，只吃轮询 `disconnectSeq`。

### 4.1 实锤调用链（2026-07-31 · HWBP + IDA）

飞天踢线时 HWBP 命中 `Nm.CloseSession`，`rsp[0]=GameAssembly+0xDDE5D0`。

| RVA | 符号（IDA 已重命名） | 角色 |
|---|---|---|
| `0x1CB9200` | `Nm.Disconnect` | **5 字节 `jmp` → CloseSession** |
| `0x1CB8550` | `Nm.CloseSession` | 真正拆 Session / CloseSocket |
| `0xDDE5CB` | call 点（在 `a480_DoLocalNetworkDisconnect` 内） | 取 SessionTcpLayer 单例后 `call Disconnect` |
| `0xDDC320` | `a480_DoLocalNetworkDisconnect`（原 `c9210241…`） | 本地断线核心（CFF 混淆） |
| `0xDDE5CB` | `call Nm_Disconnect`（返回 `0xDDE5D0`） | `Nm_Disconnect` **=`jmp Nm_CloseSession`**（无独立栈帧） |
| `0xDC86C0` | `Game_InvokeLocalNetworkDisconnect`（`d51004b88…`） | 调 `a480`；飞天踢 CloseSession 栈 `#7` |
| `0xDC7E70` | `Game_SetFlag298_ThenLocalDisconnect`（`c5968fe4…`） | 写 `this+0x298` 后调 `d510`；栈 `#8=DC844D` |
| `0xDDC2F0` | **`OpRecv_01B0_ForceDisconnect`** | **S→C opcode `0x1B0`(432)**：同样写 `+0x298` → 直接 `a480`（飞天踢 RING **无** 432） |

### 4.2 飞天踢双阶段（IDA + HWBP 实锤）

```
[线程池] Session.CallbackRecv (0x1CCA4C0)
    EndReceive → err!=0 || n==0
    → Session+0x60 = Disconnected          ← HWBP_WRITE rip=0x1CCA82D
    → return（此处不 CloseSocket）

[~140ms 后 · 另一线程]
Game_SetFlag298_ThenLocalDisconnect (0xDC7E70)
    → this+0x298 = flag
    → Game_InvokeLocalNetworkDisconnect (0xDC86C0)
        → a480_DoLocalNetworkDisconnect
            → Nm_Disconnect (=jmp CloseSession)
                → Session.CloseSocket → Socket.Close
```

含义：TCP 先死（对端 RST/FIN 或链路错误）→ 客户端 Recv 回调改态 → 游戏逻辑再走与 432 **同构** 的本地拆线（`+0x298`），但 **不是** 432 包触发。

其它调用 `DoLocalNetworkDisconnect` 的入口（非仅 432）：`0xDC86C0`、`0xD13810`、`0xDD56E0`。

**含义**：至少存在一条 **服端发包 432 → 客户端主动 `Nm.Disconnect`** 的路径；RING 若未采到 432，可能是 25ms 轮询漏采，或飞天踢走了同函数的其它入口。态字段常被 **直写**（`OnDisconnect` 入口即 `mov [rcx+60h],imm`，不经 setter），故改用 **DR2 写断** 抓 `rip`。

验证：`kick.log` 找 `via=HWBP_WRITE edge=Session.SessionState@write extra=0|1` + `rip GameAssembly+…`，对照 RING `op=432 hint=ForceDisconnect? *`。

IDA 已知写 `Session+0x60` 的站点（写断 `rip` = 站点下一条）：

| 写点 RVA | 解密后值 | 备注 |
|---|---|---|
| `0x1CC7A50` | `edx`（setter） | `mov [rcx+60h],edx; ret` — 实机 setter 执行断曾 0 命中 |
| `0x1CC927B` | **1** Disconnected | `OnDisconnect` 入口本体（xor 常量 → 1；极短 stub） |
| `0x1CC8A3D` / `0x1CCA2E8` | **1** | 其它 CFF 直写 |
| **`0x1CCA82A`** | **1** Disconnected | **`Session.CallbackRecv`（`0x1CCA4C0`）**：`EndReceive` 出错或 **0 字节** → 直写态；飞天踢实锤 `rip=0x1CCA82D` |
| `0x1CCCAFD` / `0x1CCCB30` / `0x1CCCBC7` | 3 / 1 / 1 | Teardown 多路径；邻近写 `pendingError@+0x40` |

### 4.2 CallbackRecv 控制流（IDA · 2026-07-31）

CMS：`Framework.Network.Session.CallbackRecv(IAsyncResult)`  
TW：`0x1CCA4C0`（已标名 `Session_ReceiveCallback`）

```
if (_isClosed) return;                          // +0x20
```

### 4.3 `DC7E70` 调用方（IDA 深挖结论 · 2026-07-31）

静态全库扫描结果：

| 引用类型 | 地址 | 说明 |
|---|---|---|
| 方法码表 | `.data+0x68B5FC8` | a480 类 methodPointer 槽（与 dump 方法序一致） |
| RUNTIME_FUNCTION | `.Sq_+0x973036C` | 展开信息，非调用 |
| **E8/E9/LEA/MethodInfo** | **无** | 无私有方法的静态 call 边 |

→ `c596…(DC7E70)` 只能经 **Il2Cpp MethodInfo 运行时间接调用**；要抓调用方必须 HWBP/MI 打入口。

同构 / 并行拆线入口（都能进 `a480` / `d510`）：

| RVA | 符号 | 关系 |
|---|---|---|
| `0xDD3810` | **`a480.Update`** | 读 `+0x298`；与 `+0x29C` float 比较；置旗后 **直接 `call a480`**（不经 DC7E70） |
| `0xDC7E70` | `a480_TryLocalDisconnect_c596` | 置 `+0x298` → `call d510`；飞天踢栈曾见 `DC844D` |
| `0xDC86C0` | `d510` InvokeLocalDisconnect | 被 DC7E70 / `a270(int)` / `OpRecv_010F` / 其它调用 |
| `0xDC8DF0` | `a480_DisconnectWithCode_a270(int)` | 调 d510；调用方含 **`OpRecv_01AE`** |
| `0xDD56E0` | 另一本地断线 | 直接 `call a480` |

字段（a480 实例）：

- `+0x298` `bool` — 强制本地断线旗（与 432/`OpRecv_01B0` 同槽）
- `+0x29C` `float` — Update 里与当前值 `ucomiss` 的节流/超时

**飞天踢双阶段不变**：CallbackRecv 先写 Session 态；随后本地拆线。DC7E70 vs Update 直调 a480 需入口 HWBP 区分（静态无法证伪栈中帧）。
  
3. Singleton：`Lazy<T>` 在父类 `Singleton<>` **静态区**；实例必须 `obj->klass == SessionTcpLayer`。  
4. **拒绝假指针**：`session == 0x8` 这类小整数 **不是** 堆地址（2026-07-30 20:05 实机曾缓存垃圾对象，全程 `err=-1`）。  
5. 合法缓存条件：`LooksLikeHeapPtr(Session*)` 且/或 `state ∈ {Connecting, Connected}`；**禁止**仅凭 `Disconnecting + 无效 session` 接纳单例。

## 5. 日志怎么读

成功路径应出现：

```text
CALL_EDGE_HWBP installed threads=N veh=…
CALL_EDGE #1 via=HWBP edge=Session.Close tid=… pendingError=…
  #0 GameAssembly.dll+0x…
  rsp[0] GameAssembly.dll+0x…   ← 直接调用方（比 MI 更能抓住硬编码 call）
STATE Connected(3) -> Disconnected(1) pendingError=N
```

| 行 | 含义 |
|---|---|
| `via=HWBP_WRITE` | DR2 写断命中 `Session+0x60`；看 `rip`/`rsp[0]` 找写字段指令 |
| `edge=a480.TryLocalDisconnect` | DR0：`DC7E70` 入口；`rsp[0]`=MethodInfo 调用方；看 `a480 flag+0x298` |
| `edge=a480.Update->DoLocalDisconnect` | DR1：`DD46B8`（Update 内 `call a480`）；走 Update 直调路径 |
| `edge=Session.SessionState@write extra=0/1` | 谁把态写成 Disconnecting/Disconnected |
| `via=HWBP` | 硬件断点命中函数**真实入口**（含直接 `call` RVA） |
| `via=MI` | MethodInfo 间接调用（直接 call 路径通常为 0） |
| `rsp[0]` | 返回地址 = 谁 `call` 了该入口 |
| `op=432 *` | TW `OpRecv_01B0` → 本地 `Nm.Disconnect`（见 §4.1） |

### RING 判读（本地自断 vs 服端踢）

| verdict | 含义 |
|---|---|
| `lean_server` | 断线前 3s 内采到带 `*` 的踢/通知类 opcode（261/269/408/143 等 CMS 提示） |
| `lean_local_or_soft` | 有 S→C 流量，但窗口内无踢人提示包 → 偏本地自断或软踢无 notice |
| `lean_local_or_missed` | ring 空 → 包在两次轮询间被消化，**或**根本无入包（本地先断） |

### `lost_session` soft（进图切会话 · 2026-08-07）

进场 / 换图时 `SessionTcpLayer` 常短暂解绑，worker 会打 `STATE lost SessionTcpLayer` 并调
`DumpRing("lost_session")`。全量 HIST+ring 每行都进 `kick.log` **和** `x.jsonl(LogI)`，
实测进场秒可到 ~47 条 KickSniff，是进图卡顿的我们侧嫌疑。

现行规则：

| 条件 | 行为 |
|---|---|
| `why=lost_session` 且近 3s 环内 **无** kick hint | **soft**：只打一行 `RING why=lost_session soft … skip HIST/ring`；3s 内抖动静默去重 |
| `why=lost_session` 且环内 **有** kick hint | 仍走全量 dump（受 15s full-dump 冷却） |
| `why=disconnect` / 其它 | 不变；soft **不占用** full-dump 冷却，避免真踢被误吞 |

读日志时看到 `soft` = 正常 churn，不是漏抓踢线。

断线时额外输出：

```text
HIST window=3000ms unique=N (fmt: op count_win/count_all hint)
  hist[1] op=283(0x011B) 18/40 hint=MobCtrlHint
  hist[2] op=77(0x004D) 1/1 hint=BroadcastMsg
```

`count_win` = 近 3s 次数，`count_all` = 整环次数。常见业务包（CMS 名，TW 可能漂移）：`283 MobCtrlHint`、`77 BroadcastMsg`、`10 AliveReq`、`276 SkillCooltimeSet`、`272 UserPassiveMove`。

`*` = `LooksLikeKickRelatedOp`。heartbeat 的 `ring=N` 应在进图后持续增长；若始终 `ring=0` 说明队列采样未命中（布局/耗尽过快）。
