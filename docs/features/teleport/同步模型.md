## 1. 分层（别混）

| 层 | 对象 / 偏移 | 含义 | 谁在正常帧更新 |
|---|---|---|---|
| 魂 / 物理 | `VecCtrl.Ap` double `@0x98` | AbsPos：站位、碰撞、发包权威 | `CalcWalk` / `CalcFloat` |
| 台坐标 | `VecCtrl.Rp` `@0x88` + `CurFh@0x28` | **有台时走路真源**（弧长 Pos/V） | `CalcWalk` 沿台积分 |
| ~~皮字段~~ | `FieldActorBase.Pos/PosPrev` `@0x64/@0x6C` | **不是视觉坐标**（已纠偏，见下方警告） | 写入方未定位 |
| **皮（真源）** | `VecCtrl.Ap@0x98` + `Apl@0xB8` | 经 `VecCtrl.GetPos()` 实时插值 → `Transform.position` | `BeginUpdateActive` 滚 `Apl`；`WorkUpdateActive` 推 `Ap` |
| 镜头 | `LocalUser.CurPos/PrevPos` `@0x240/@0x248` | 逻辑跟随；静止常 `Ap+(0,~11)` | 引擎维持双空间 |
| 渲染 | `UserBase.AvatarRoot` / `RendererTransform` | Unity TRS | 引擎从皮/动画推 |
| 动作 | `VecCtrl.MoveAction@0x84` + `FieldActorBase.MoveAction@0x58` | Stand/Walk/Alert/Attack… | `SetInput`→`OnResolveMoveAction` |

> ⚠️ **2026-08-02 纠偏**：本表原把 `Pos@0x64` 标为「角色视觉坐标」，**不成立**。
> 反汇编实证：写 `Transform` 的那个虚函数（`FieldActorBase` Slot 16 `@0x1197330`）全程**没有一条指令读 `+0x64`**，
> 它读的是 `VecCtrl.Ap`/`Apl` 并经 `VecCtrl.GetPos()@0x1176CC0` 插值。往 `Pos@0x64` 写坐标不会让精灵移动。
> 完整链路、门控与逐症状对照见 [`P0c_视觉层同步链.md`](P0c_视觉层同步链.md)。

静止经验式：

- `Ap ≈ Pos@0x64`（身体）
- `CurPos ≈ Ap + camOff`（镜头，本图 camOff.y 常 ~11，不是身体）

## 2. 正常走路主链（引擎自同步）

本地玩家在 **`VecCtrlUser.WorkUpdateActive`（RVA `0x11CFA90`）**：

```text
KeyPad 采样
  → 锁存对象 *(vc+0x100)+0x10/0x14
  → SetInput(锁存X, 0)          // 写入 InputX@0x50，并 OnResolveMoveAction
  → 基类 WorkUpdateActive
       └─ CalcWalk(tElapse)     // 读 InputX；有 FH 时积 RelPos → 更新 Ap
  →（再 SetInput 一次，Y=0）
```

要点（`docs/features/protocol/MoveElem字段.md` §11.6 已 IDA 实锤）：

1. **基类 `EndUpdateActive@0x11AD910` 是空实现（`ret`）**——皮跟随不是靠这个空函数。
2. 走路积分真源是 **`CalcWalk` + RelPos/FH**，不是每帧 `Transform.set_position`。
3. 只写 `InputX@0x50` 会被同帧 `SetInput(锁存)` 盖掉；方向键走的是 KeyPad→锁存→SetInput 官方链。
4. `SetInput` 会走 `OnResolveMoveAction`：改动作态（Walk/Stand/朝向）。**乱调 `SetInput(0,0)` 等于抢状态机。**

## 3. Attr=4 瞬移在打断什么

`MovePathType`：**4 = Teleport**。

我们的旁路（ImpactNext 探针 · 禁 Transform 回退）：

```text
Mp 落点坐标 + 挂 CurFh → Attr=4 + ForcedFlush → SetImpactNext(dx,dy)
（不预写 AbsPos；不写 Pos/Transform/VisualLeash）
```

对照原生落地 helper（[`P0a`](P0a_瞬移CALL锚点.md) §2.1）：官方同样调 **`SetImpactNext(vx,vy)`** 交给下一帧 `WorkUpdateActive` 消费，再顺带 `EffectGeneral`；**不**外挂 `Transform.set_position`。

> ⚠️ 别把 `SetImpactNext` 读成「它负责把角色送过去」。它写的是 `Ap.Vx/Vy`（px/秒）并置 `Valid`；
> 我们旁路的超距位移主要来自**上一步「挂 CurFh 到目标踏板」**——引擎消费 impact 时会据此重算 `RelPos → AbsPos`。
> 语义、消费链与证据见 [`P0b`](P0b_引擎实现原理.md) §2 / §3 / §4。

**产品长距 API**：`TeleportNativeSkillCall(land, fh, snapStand)`（贴怪 snap=1；点飞 snap=0）。  
~~`ImpactBlinkTo` / `TeleportTo`~~ 已拆除。Settle 由官方 Doing 收态，不再跑 Impact settle 泵。

本探针只测 ImpactNext；失败即失败，**不**回退硬钉 Transform / walk-gated 牵绳。

## 4. 双空间（镜头）铁律

| 写错 | BIN 后果 |
|---|---|
| 把 `CurPos` 当身体写进 `Ap` | 瞬移 +camOff → 踢 / Y 锁 |
| 把身体写成 `CurPos` | 「只动皮肤、位置混乱」 |
| 学坏 `camOff≈109` 再写回 | 关 F5 失操控 |
| 正确 | `CurPos = Ap + restCamOff`（oy∈(5,40]，默认 11） |

## 5. 收态禁区（已用 BIN 打穿）

| 操作 | 后果 | 结论 |
|---|---|---|
| 每跳 / soft 调 `SetInput(0,0)` | **只砍一刀 + 态乱** | **禁止**作为常规收态 |
| 站地硬 `ForceStand`（非 Jump/Fall） | 攻击 SM 卡住、精灵像定帧 | 仅 raw=3（空中）可拧 Stand |
| sticky 无门控每帧 `Transform` | 皮跟魂，但抢动画 / 一刀后冻 | **禁止** |
| walk-gated Transform（有 Input/速度才写） | 走时跟皮；站桩出刀不抢 | **Attr 旁路后过渡方案** |
| `AbsPos←RelPos` 回写 | 魂被拉回、皮留原地 | **禁止**（Rel 只←Abs） |
| 只写 Ap、不钉 Pos | 魂到、皮留原点 | ⚠️ **旧结论「要钉 Pos」已证伪**；真因是 `Apl`/`RelPos` 未同步 → 应补 `Apl` |
| 只钉 Pos、不钉 Transform | 魂到、皮仍不到落点（本次 BIN） | ✅ 现象属实，因 `Pos@0x64` 根本不参与 TRS；一次钉 TRS 可行，**补 `Apl` 更干净** |

## 6. 目标收态（引擎自同步）——设计约束，尚未全部 BIN 通过

落点（一次）：

1. Ap + MovePath XY  
2. Plant CurFh + `RelPos.SetFromAbsPos`  
3. Attr→Normal，ForcedFlush=false  
4. ~~钉 `FieldActorBase.Pos/PosPrev`~~ **无效** + **一次** `Transform.set_position`  
   → **改用**：`Apl.X/Y@0xB8/0xC0` ← 落点（与 `Ap` 同值），插值即刻收敛，无需碰 TRS  
5. 修 `CurPos = Ap + restCam`（只动镜头层）

之后：

- **不再** SetInput / 硬 ForceStand / 每帧拉 Transform  
- soft 可再刷 Pos/CurPos，**不要**再钉 Transform  
- 方向键走 KeyPad 官方链 → CalcWalk → RelPos/Ap → 引擎经 `GetPos()` 插值推 TRS（**不经 `Pos@0x64`**）  
- 攻击走 OnFuncKey，由 OnResolve 自己改 MoveAction  

落点一次钉 TRS 是可见瞬移的底线；**持续**钉 TRS 才是冻皮根因。

> 📌 **2026-08-02 补充机制**：这条经验为什么成立，已在 [`P0c_视觉层同步链.md`](P0c_视觉层同步链.md) §7.2 打穿——
> 落点时 `Ap` 已到位但 `Apl` 仍是旧点，`GetPos()` 会插值滑行 ≤30ms，一次钉 TRS 就是在盖掉这段滑行。
> 第 4 步里的「钉 `Pos/PosPrev`」**是无效动作**（`Pos@0x64` 不参与 TRS）；
> 更干净的等效写法是把 `Apl.X/Y` 一并写成落点，见 P0c §8。改动前请先跑 P0c §8.2 的实验一。

## 7. 与本仓旧表述的纠偏

| 旧说法 | 纠正 |
|---|---|
| `LocalUser@0x64` 是视觉 | 实为 **`FieldActorBase.Pos@0x64`**（LocalUser 继承链上的同一对象布局） |
| 靠 `EndUpdateActive` 推皮 | 基类 EndUpdate **空**；走路靠 **WorkUpdateActive→CalcWalk** |
| `Pos@0x64` 是视觉坐标 | **不是**。视觉真源 = `VecCtrl.Ap`/`Apl` 经 `GetPos()@0x1176CC0` 插值；见 [`P0c`](P0c_视觉层同步链.md) §6 |
| soft 必须 SetInput 才能走 | SetInput 能 Resolve，但会掐刀；应优先保证 Attr/FH/RelPos，让 KeyPad 链自己 SetInput |
| sticky VisualLeash 可长期代同步 | 只可作实验，**不是**产品路径 |
