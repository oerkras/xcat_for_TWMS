## BIN 现象

测试贴怪瞬移后：**皮（精灵）留原地，魂（可打/可走逻辑点）到落点**。  
说明「只写 AbsPos」动的是物理/服端权威层，不是渲染层。

## 结论

> 以下 4 条是 08-01 的原始结论，**第 2 / 4 条已证伪**，保留原文以存档，纠正见每条下方。

1. **AbsPos 不是写错了**——它是魂/物理真源；服端认它（怪能打到落点）。  
   → ✅ 仍成立，且比当时以为的更强：`Ap` 同时是视觉插值的**终点**。
2. ~~**缺的是视觉层**：`VisPos@0x64` + `Transform.set_position`（及 CurPos 双空间）。~~  
   → ❌ **`@0x64` 与视觉无关**。真正缺的是 `Apl@0xB8/0xC0`：不同步它，`GetPos()` 就会从旧点插值滑过来。
3. 老项目**从来不是「只写 AbsPos」**：HuntTP / 枫星飞都是 **物理 + Transform 双钉**。  
   → ⚠️ 那是**别的客户端**的做法。经典版引擎自带 `Ap→Apl→GetPos→TRS` 链，不需要外挂 TRS，写 `Apl` 即可。
4. ~~原则修正：「不硬写 Transform」只适用于**走路帧由 EndUpdateActive 自同步**；**Attr 瞬移旁路**打断了该链，必须显式钉皮。~~  
   → ❌ 双错：① `EndUpdateActive` 是**空函数**，从来没推过皮；② 旁路打断的不是「自同步链」，
   而是让 `Apl` 与 `Ap` 脱节；补 `Apl` 比钉 TRS 更干净。见 [`P0c`](P0c_视觉层同步链.md) §7.2 / §8.1。
