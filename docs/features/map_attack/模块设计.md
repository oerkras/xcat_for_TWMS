## 0. 一句话

全图攻击 = **在官方 `OnFuncKey` → `TryDoing*` → `FindHitMobInRect` 链上，把「攻击盒 ∩ maxCount」放宽到「本图活怪 ∩ 技能 MobCount ∩ 包 flags 上限 15」**。  
出刀真源仍是 A 键绑定（技能或普攻）；**不**手搓 opcode 50/51/52 把全图 oid 塞进 BODY。

若 P2 BIN 证明服端按距离砍掉盒外怪或踢号：本功能结案为 **不可做**，关掉，禁止回退到造包。

## 1. 为什么必须新模块（禁止掺进现网）

现网三套出刀已经各管各的，全图再塞进去会把语义绞死：

| 现网 | 职责 | 全图若掺进去 |
|---|---|---|
| `simple_combat` | 选怪 / 贴怪 / `OnFuncKey` | 改 Firing = 破坏打怪状态机 |
| `hit_pin_port` | 打中换怪：FindHit **之后**滤成锁 oid | 全图要的是「多 oid」；和「只留一只」相反 |
| `attack_rpc` / `simpleCombatForgeHit` | 实验自组包（默认关、不落盘） | 全图 oid 列表 = 已否决的踢号路径 |

**硬规则**：本 feature 落地时，`simple_combat.cpp` 的 Firing / Recover **零 diff**；`attack_rpc_port` 的 Encode/Send **零 diff**；打中换怪的滤名单语义 **不改**（关全图时 hit_pin 行为与今日比特级相同）。

## 2. 已否决（写进方案，避免下轮再提）

| 想法 | 否决理由 | 证据 |
|---|---|---|
| 「造包能真伤，把全图怪都写进包」 | 真伤来自 `OnFuncKey`，不是组包；组包 3～4 发 ~109ms 踢 | 2026-08-14 combat.log / KickSniff |
| 一包塞全图 oid | `flags` 高 nibble = mobCount，**最多 15** | P0c；`kMaxMobsHard=15` |
| 每只怪一包轮询 | 同造包洪水；type20 窗 60s/2000 | `攻包计数窗与type20.md` |
| 普攻飞镖全图 | 射击 `FindHit` 一处种子实算 **maxCount=1** | ShootAttack `r9d = 0xC3A1CECC xor seed → 1` |
| 与「打中换怪」同时开 | 一个要多目标，一个要钉一只 | 产品互斥 |
| 与「出刀自组攻包」同时开 | 组包绕过 FindHit，扩盒无效 | 产品互斥 |
| 改 `Session.Send` / GA `.text` 除约定 AbsHook 外的 E9 | 现网安全红线 | attack_rpc / hit_pin 先例 |

普攻（A 空 / `t=5 v=52`）**不能**作为「一刀多怪」验收。官方 NA `maxCount=1`，扩盒后仍一刀一只。  
**可以**作为 P2 远距单目标 BIN：盒换成全图 AABB，看 `oid0` 的 `dx/dy` 和那只怪 hp。一刀多怪仍要 A 槽绑 `SkillLevelData.MobCount ≥ 2`（DUMP：`MobCount@+0x98`）。

## 3. 真源（IDA / DUMP · 已采）

```
OnFuncKey(A 槽 FuncKey)
  → TryDoingMelee / Shoot / Magic
       → 按武器 Range / 技能 rcAffectedArea 拼 Rect
       → MobPool.FindHitMobInRect(Rect, List, maxCount, …)   RVA 0xF877F0
            r9 = maxCount（普攻射击位点已解出 1；技能位点跟 MobCount）
       → 官方 Encode 命中环（flags 高 nibble = 列表.count）
       → Network_SendOutPacket
```

客户端认的名单 = **盒内 ∩ maxCount**。  
服端还会再核范围 / 数量 / 技能 id（本仓没有服端源码；P2 用「盒外怪掉不掉血」BIN 反推，不猜私服逻辑）。

当前 IDB：`Dumps/runtime/GameAssembly.dll.i64`（本轮 imagebase `0x7ffd72820000`，RVA 随 remount 核）。

P0a 已钉死（细节与种子表见 P0a 笔记）：

- `Rect` = UnityEngine.Rect，**float `x,y,w,h`**，世界 AbsPos；技能盒 = `rcAffectedArea@+0xAC` + `Rect.Offset(角色坐标)`。
- 技能 `maxCount` = **`SkillLevelData.MobCount@+0x98` 直读**；普攻射击 / 近战 NA 种子实算均为 **1**。
- 地图盒用 `map_bounds::QueryPlayBounds` 的 ltrb int，**禁止 memcpy**，必须换成 xywh float。

## 4. 产品行为（开关开时）

1. 用户照常 F5 打怪或空手按 A，出刀仍走 `OnFuncKey`。  
2. 本模块在 **FindHit 入参**上动手（见 §6）：Rect → 当前地图 foothold AABB（ltrb int → xywh float）。**不抬 `maxCount`**（NA 保持 1；抬高会和官方技能数据打架）。  
3. `maxCount=1` **仍然扩盒**：一刀仍一只，但这只可从全图盒里挑。AABB 失败则不改、打 `why=no_aabb`。  
4. 官方 Encode / 发包 / 简单战斗状态机全部不动。  
5. 关：回调空，FindHit 入参原样；与未装本模块时一致。

非目标：改伤害数字、改技能 CD、吸怪、改怪物坐标、代替 F5 选怪。

## 6. 钩子所有权（避免破坏 hit_pin）

`hit_pin_port` **已经** AbsHook 了 `FindHitMobInRect`。全图再 E9 同一 RVA = 两套 trampoline 互踩。

**选定方案（已落地）**：

- 不抢 E9。在 `hit_pin` 的钩子入口加可选 `BeforeFindHit` / `AfterFindHit`，默认 `nullptr`。  
- 关全图：指针空，现网路径零开销（仍：原函数扫描 → 若 wishOid≠0 则滤名单）。  
- 开全图：`map_attack_port` 注册回调，**只改 `Rect*`，不改 `maxCount`**，然后仍走原函数。  
- 打中换怪与全图互斥：payload 层保证 `wishOid=0` 且 hit_rotate 关，滤名单不会把全图结果打回一只。

允许的 hit_pin diff（落地时单列，review 用）：`hit_pin_port.h/.cpp` 增加回调 typedef + 调用点，**不改** `PinListToOid` 逻辑。除此之外 hit_pin 行为不变。

备选（若拒绝碰 hit_pin）：在 `TryDoing*` 的 FindHit **call site** 改 Rect / r9。CFF 跳转表多、remount 脆，**不作为首选**。

禁止：map_attack 自己再 AbsHook 同一 RVA。

## 9. 验收（P2 近战 NA 扩盒）

通过：

- 开关关：`combat.log` 仍是 `fire id=` / `path=OnFuncKey`；无 `MapAtk` `exp=1`。  
- 开关开 + 近战普攻：`exp=1 why=aabb`，`xywh` 的 w/h 远大于 P1 的 80×67；`mc=1`、`n` 仍 ≤1。  
- `oid0` 的 `|dx|` 或 `|dy|` 明显大于武器盒（走开近怪再打）；该 oid 对应怪 **hp 下降**。  
- 与打中换怪 / 组包互斥：强开其中一个，另一个被打下并打 Warn。

失败（功能废弃，不是「再造包补」）：

- 名单变多但远处怪 hp 不变（服端砍范围）。  
- 断线 / `KickSniff` 与开本项时间相关。  
- `hit_pin` 关全图后仍与基线 diff（钩子链破坏）。

## 10. 风险

| 风险 | 处理 |
|---|---|
| 服端范围核 | P2 BIN 一票否决；不承诺「全图」字面 |
| flags 只有 4 bit | 硬顶 15，多的不进包 |
| remount 后 FindHit RVA / 种子漂 | 与 hit_pin 同 RVA；shape/prolog 校验失败则拒装回调 |
| 技能 BODY 比普攻多字段 | 本模块不 Encode；走官方 TryDoing，技能包由引擎组 |
| 用户把「全图」理解成秒图 | UI 写明：普攻仍一刀一只；测的是远距那一只 |
