> **真源**：`Dumps/runtime/out/dump.cs` 类哈希 **`ab85c0a92566c06894823c0ea737161a6102c41812458909864735c34f99947`**（2026-08-03 remount；旧 `a480358a…` 已不在新 dump）  
> **对照**：`Dumps/cms_cw/dump.cs` `WorldManager`（CMS 偏移**不可直接用**；TW 在 CharacterData 一带已漂）  
> **用途**：本机世界态总枢纽。下列「CMS 名」为结构对齐推断；带 ✅ 的为本仓代码实锤。  
> **本仓解析**：WM 实例**只**经 `ports::world::GetWorldManager()`（`x/features/ports/world_port.*`）；禁止各模块再 FindAll(WM)。

`SceneState`（CMS ≡ TW 枚举序）：`None=0 / InterStage=1 / Login=2 / Field=3 / CashShop=4 / GlobalMarket=5`。

## 2. 经 WM 一跳：CharacterData（`WM+0xE0`）

类型 `e410fb71…`（TypeDefIndex 1832；旧文档 `e8315303…` 已过期）。  

**运行时防漂 SSOT**：`x::ui::player`（`player_vitals`）+ 转发 API `ports::world::GetCharacterData/GetCharacterStat/ReadMoney/GetItemSlotList`。  
字段走 hash → `field_get_offset`；常量仅 fallback。日志：`Vitals field off … money=… itemSlots=… skillRec=… coolOver=… ss=… path=`。  
`WM.MyUser`（hash，fb`@+0x28`）经 `LocalMyUser()` / `OffWmMyUser()`；`skill_port` 绑 LU 已改走此 SSOT。

| `+0x40` | **`ItemSlots`** `List<ItemSlotBase>[]` | player_vitals / shop / pet ✅ |
| `+0x50` | **`SkillRecord`** Dict | player_vitals / skill_port ✅ |
| `+0x58` | **`SkillRecordEx`** Dict | player_vitals / skill_port ✅ |

## 3. 经 WM 一跳：Field（`WM+0x58`）

`Field : SceneMap`。自身含多层 `GameObject` 根、`ChangingObject` 字典、静态 `Field` 单例属性等。  
**怪池 / 掉落池通常是独立 Singleton**（`MobPool` / `DropPool`），不一定是 Field 字段；进图后用 Singleton 或经 Field 场景对象找更稳。

## 4. 经 WM 一跳：MapData（`WM+0x88`）

| 用途 | 锚点 | 本仓 |
|------|------|------|
| 地图 Id | `MapData.Id` | mobscan `map=` |
| 刷怪槽 **M** | `LifeList@+0x38`，`MapLifeData.Type==Mob(1)` | mob_pool_port ✅ |
| 活怪 **n** | `MobPool` 字典 + 存活过滤 | mobscan / titlebar `怪 n/M` |

> **n ≠ M**：M 是刷怪点容量，n 是当前活怪；经典单人图经常不满槽。实现与引擎说明见 [`mob_pool/活怪n与刷怪槽M.md`](../mob_pool/活怪n与刷怪槽M.md)。
