## 1. 做什么 / 不做什么

| 做 | 不做 |
|---|---|
| 断线后 `SceneLogin` ConnectLogin（RVA `0xC039D0`）试连 | 清浏览器 / Gama Pass 登录态；改 OAuth `prompt` |
| 关踢线/断线弹窗（`CloseDialog` / `SetActive(false)`） | 点「確認」/ Yes / Ok（会走踢登录） |
| `RequestRestart("soft_login")` 重跑选区选角 | 跳过 PickWorld / 裸调 `TriggerEnterChannel` |
| `softLoginHold` 推迟守护干净重拉，直到 play-ready 或完全失败 | 进程仍活时被其它 watchdog 理由误杀重拉 |
| WM `Login` / 卡死 `InterStage` 且已进过图 → `stuck_lobby` | 冷启第一次选区（`IsDone=0`）抢跑 |
| 成功标准 = pump 上 `IsPlayReady`（吞 `disconnectSeq`） | 仅 NM Connected 就算成功 |

## 2. 闭环时序

```
disconnectSeq
  → settle_dismiss（Util/Ex + Notice 白名单；永不 FindAll UIDialog 基类）
  → [若已 Connected 且 SoftHall.ready] 跳过 ConnectLogin → dismiss+reenter
  → 否则 ConnectLogin（含「Connected 但 WorldItems=0」的书页大厅；SoftPumpCall = High）
  → NM Connected
  → dismiss_miss 可继续
  → **等大厅可点分区**（`WorldItems>0` 或频道页已挂选中世界；最长 ~6s）
       └ 超时 → soft cycle（下一轮再 ConnectLogin 刷新；勿空 `RequestRestart`）
  → auto_enter RequestRestart(why=soft_login)  ← softFast=1
  → 选区→选频→GoWorld→选角→Confirm→Done
  → 等 IsPlayReady
       ├ success → RESULT success · 放 hold · 吞 disconnectSeq
       │          （inMap 时 skip post-dismiss，保护 UIMiniMap）
       └ fail / WorldItems 饿死(~10s) / auto_enter Failed → soft cycle 或放 hold
```

### 2.1.1 大厅场景兜底（`stuck_lobby`）+ land_quiet 真断线

`Disconnected` 边沿会漏（`lost_session` 被吞、MapScene 残留、没有 STATE 边沿）。worker 空闲时 off-pump 读 WM：

| 要 | 不要 |
|---|---|
| `Login` **或**（`InterStage` 且 `!inMap`）连续 ≥2s | 只认 `Login`（本机 BIN 01:23:52 回大厅后 scene 停在 1，从未到 2） |
| `auto_enter` Desired 且 **Done 或 Failed** | 冷启第一次 `WaitWorldList`（`IsDone=0`） |
| 不要求泵上 `SoftHall.ready` | 泵新鲜度 / quiesce |

### 2.2 关窗（dismiss）边界

**正式关窗路径（2026-08-10 收口 · `1ab84c` 验证）**：

| 步骤 | 做法 | 禁止 |
|---|---|---|
| 关法 | 实例上调 **`UIUtilDialog.CloseDialog`**（RVA `0x778CC0` → `UIDialog.Close`），再 **`SetActive(false)`** | 点「確認」/ `OnClickYes` / `OnClickBtOk`（踢线场景=认踢） |

实例指针真源：游戏对 `UIUtilDialog.Notice`（RVA `0x74ACD0`）是 **直 call**（≥400 处），不经 `MethodInfo.methodPointer`，故 MI 换针永远 `cache=0`。Abs trampoline 实现已写在 `soft_login_probe.cpp`（`kNoticeAbsEnabled`），**默认关闭**——等后续测稳再开；现行 dismiss **只走 FindAll**。验收以 `close≥1` + 窗消失为准。

| 扫什么 | 不扫什么 |
|---|---|
| `UIUtilDialog` / `UIUtilDialogEx` | **`FindAll(UIDialog 基类)`**（子树含 UIMiniMap 等 HUD，约 121 类） |
| Notice 白名单（`scanBase=1`）：`UINoticeDialog` / `UILoginUtilDialog` / `UISlideNotice` / `UIMultiLineNotice` / `UIAntiMacroNotice` / `UIMultiLine` | 背包/技能/任务闹钟/组队血条等常驻或面板 UI |
| 纵深 | `IsProtectedFieldHud` 跳过 `UIMiniMap` |
| Abs 捕获（保留代码，`kNoticeAbsEnabled=false`） | 未启用；不能替代 FindAll |

日志指纹：`settle_dismiss` / `dismiss try=` / `post_dismiss_light` / `miClose=1` / `close=`（Abs 开后另有 `Notice Abs install ok` / `cache=` / `abs=` / `hits=`）。

### 2.4 守护 hold

`softLoginHold=1` 且进程仍活：挂机守护 **禁止** 一切干净重拉。  
仅 `softLoginResult` 失败（2）或进程已死才允许重拉。

#### 2.4.1 最小 hold 时长（`kMinHoldMs` = 2s）

Status SHM 每 **500ms** 才发布一拍（`payload_status.cpp` `kPublishIntervalMs`），而守护吞 `disconnectSeq` 只认 `softLoginResult` 的 **0→1 上升沿**（`hangup_schedule.cpp`）。attempt 若整段落在同一拍内，「result=0 / hold=1」这一拍会整体消失，守护只看到「seq 涨了且 hold=0」→ 判服务器踢线 → 干净重拉杀进程（BIN 17:29 实测 hold 仅 13ms）。

现在 `Finish` 会把 hold 按住到 attempt 起点后至少 `kMinHoldMs`，保证守护先采到观察窗、再采到 RESULT；等待期间 land quiet / post-air 闸同步顺延（`ExtendQuietWindows`）。日志指纹 `min_hold +Nms attempt=Mms`。

#### 2.4.2 图内确认恢复（`kInMapRecoverConfirmMs` = 2s）

真断线 why（`disconnected` / `disconnecting` / `close_session_inmap` / `stuck_lobby` / `mob_gather_*`）下，`MapScene` 残留 **不得** 判 `already_in_map` 成功。但「残留」与「游戏自己恢复了」必须能分开：`playReady + curFh≠0 + NM Connected` 连续稳住 **2s** 即 `RESULT success in_map_recovered`。

BIN 8cab31：角色早已挂台 `curFh=47`，cycle_begin 仍去 ConnectLogin，空大厅 `WorldItems=0` 空等 12s，确认钟被闪一拍 `!inMap` 清掉后再盯 8s，体感「落地很久才提示软重连成功」。守护误杀根因是 hold 只闪 13ms（`kMinHoldMs` 已盖住），不是还要再盯 8s。现在 cycle_begin 一旦起表就 `wait_out` 把确认窗等完，禁止再拆大厅；闪一拍 `!inMap` 给 500ms 宽限才清钟。面板 `soft-login-ok` 豁免 30s 签名去重，成功气泡跟 RESULT 走。

BIN 9cbbfb（0.1.149）：`mob_gather_timer` CloseSession 后 cycle_begin 仍是 `curFh=422 ready=1`，但 NM 是 Disconnected —— **不得**在此时起表认成功，否则会把清怪重连掐死。真正晚气泡发生在后面：`auto_enter Failed` → `WaitHallPickReady` 空等 12s（`items=0`，人已回图且 NM Connected）→ 超时才 `hall_wait_timeout` 起 2s 确认。现在大厅等待每一拍都探图内，挂台+Connected 立刻 `wait_out`，不再空耗剩余 12s。cycle_begin 仍要求 Connected 才起表。

没有这个出口时，假断线边沿会让 connect-wait 每轮落进 `im<0` 分支（该分支在 `++emptyHallConnect` 之前，空大厅早退口不累加），空耗 160 轮 × 10 cycle ≈ **十分钟 hold 停打怪**，最后 `Finish(2)` 反而把好端端在图里的客户端交给守护杀掉。

判定读 `gWhyNeedsReconnect` 原子量而非 `gWhy` 裸缓冲：后者 `memset`+`strncpy_s` 的中间态会被读成空串，又把假成功放开。

#### 2.4.3 连续失败熔断（3 次 / 5 分钟 → 停接管 5 分钟）

`softHoldBlocksRelaunch` 会把 hold 期间守护的 Restart 决策整个回滚，而 `reloginHardFailed` 是每拍重算的 input（`result=2` 只有上升沿有效）。失败后立刻再 hold 可以无限架空守护。现在窗口内连续 `Finish(2)` 满 `kSoftFailBreakerMax` 就停止接管 `kSoftFailBreakerHoldOffMs`：`RequestAttempt` / `RequestDeferredAttempt` 在 `SetHold` 之前早退（hold 保持 0），让守护干净重拉一次。日志指纹 `fail_streak` / `breaker ON` / `breaker off`。

> ⚠ **窗口口径**：熔断数的是 **attempt 级** `Finish(2)`，而单个 attempt 最长 ≈ `kSoftCycleMax`(10) × 单周期。若单周期被拖到 ~55s，失败间隔就有 554s > 窗口 300s，`gFailStreak` 每次都在 `NoteSoftFailure` 里被重置成 1 —— 熔断永远攒不满，守护也永远等不到重拉窗口（BIN 21:11 外机实测：3 次最终失败全打印 `fail_streak 1/3`，`breaker ON` 一次没出现，32 分钟无恢复）。**新增判死出口时必须核对「满额耗时 × 3 < 窗口」**，否则出口形同虚设。

#### 2.4.4 中间态判死（`connect_wait_limbo`）

客户端可能塌在 **登录场景已销毁、地图场景没建起来** 的中间态：此时 `SceneLogin` 实例不存在，而它正是 `ConnectLogin` 的唯一入口 —— 重试没有着力点。BIN 21:11 外机实录：换频 Confirm 在途 52s 无回音 → `AutoEnter phase timeout → Failed(phase=10)` → 主泵进 `interstage quiesce` 并再没出来（667 次 `reject non-High`，稳定 20 次/分直到日志末尾）；soft_login 连打 **1130 轮 `detail=sl_null`**，32 分钟零恢复。

| 项 | 约定 |
|---|---|
| 一轮命中 | `sl_null` **且** `slOk=0`（同轮两次窥探一致）**且** `state ∉ {Connected, Connecting}`（`SampleLooksLimbo`） |
| `kLimboConnectRounds` | **72**（实测轮距 347ms → ~25s）；健康自连 2s 内就转 `Connecting`，会打断计数 |
| `kLimboSoftCycleMax` | **2** 个连续 limbo 周期 → `Finish(2)` 放 hold 交守护（≈50s/attempt，3 次 ≈150s 落在熔断窗 300s 内） |
| 满额先排除图内 | `SoftProbeInMapOrFinish("limbo")`：`im==1` 走成功出口；`im<0`（读不出）**退 8 轮再重探**，不拿未知判死 |
| 逃逸口 | 状态转 `Connecting`/`Connected`，或 `SceneLogin` 重建 → `limboRounds` 归零 |

**判据禁忌**（三条都踩过，全部有 BIN 21:11 实证）：

- **不得**用 `nmOk`：`ResolveNmFacadeOnPump` 只取 statics 里第一个像堆指针的槽，**不校验 session/state**，塌成中间态时照样返回非空。kick_sniff 心跳里 `nm=0` 是因为 `LooksLikeNetworkManagerFacade` 带校验，两者不同源，不能互相推断。**连复位点也不许按 `nmOk` 写**：`nmOk` 在中间态恒真，会让每轮先清零再自增，`limboRounds` 永远到不了阈值 —— 复位口径必须与逃逸口一致，只认「状态转 `Connecting`/`Connected`」。
- **不得**用 `hallReady=0`：中间态下 `SoftHall` 仍报 `ready=1 items=2` —— 登录 UI 对象滞留在堆里，只有 `SceneLogin.Instance` 为 null。同一份日志里 `stuck_lobby detect world=1 ch=1 items=2` 打了 3 次，而那条正是 `hall.ok && hall.ready` 才打印；加这条判据会让出口**永不触发**。
- **不得**用「泵在 quiesce」：它在登录大厅期恒真（见 §2.1 末行），拿它判死会把正常登录一起杀掉。

**判死路径可达性**（必须核，否则出口是死代码）：`SoftProbeInMapOrFinish` 只在 `play.sampled && !play.inMap` 时返回 0。当晚 `WorldPort scene=1 inMap=0`、`Titlebar not play ready` 持续成立，主泵活着（High 调用能通，`DoConnectOnPump` 成功返回 `sl_null` 1130 次），故返回 0、给出口放行；`needReconnect=1` 也挡住了 §2.4.2 的 off-pump 假成功。

**已知宽松处**：`limboStreak` 只在 limbo 失败点传入 `SoftFailOrRetry`，其余失败点传 `nullptr`（与 `emptyHallStreak` 同一既有形制），故「limbo → pump_dead → limbo」不会重置计数，会比严格「连续」早一轮交守护。因单个计数周期已要求 72 轮连续 limbo（~25s），两周期 ≥50s 真中间态，判死仍成立，故保留现形制。

日志指纹：`limbo watch rounds=N/72` / `connect_wait limbo_defer` / `RESULT fail connect_wait_limbo` / `limbo give_up streak=N`。

#### 2.4.5 拍卖 / 商城迁服（`in_market`，勿当成回大厅）

野外点拍卖走的是 `WorldManager.SendMigrateToGlobalMarketRequest`：**客户端主动迁服**，游戏自己关掉当前会话再连市场服。`kick_sniff` 看到 `Connected→Disconnected` 会 `RequestAttempt("disconnected")`（**hop `IsMigrateInFlight` 除外**：已发包迁频抖由 hop Fail 后再拉，避免双主），而此时 `IsInMapScene()` 必为 0 —— 旧逻辑据此判「角色回到大厅」，接着走拆大厅 + `ConnectLogin`，把正在逛拍卖的用户拽回登录流程。进商城（`CashShop`）同理。

| 项 | 约定 |
|---|---|
| 判据 | `GetSceneState() ∈ {GlobalMarket=5, CashShop=4}`（`SoftSceneIsMarket`），off-pump 直读 |
| 收尾 | 与 `already_in_map` 同口径：`ArmLandQuiet` + `Finish(1, in_market)`，跳过拆大厅/`ConnectLogin` |
| 复查点 | `SoftProbeInMapOrFinish` 开头（覆盖 `cycle_begin` 等所有决策点）+ **connect-wait 每轮** |
| 气泡 | 不弹「软重连成功」（本轮压根没重连），改弹 Info「拍卖/商城迁服」（30s 节流，日志不节流）；attempt 起点的「试连中」同样跳过 |

**为什么必须先接下 hold 再报成功，而不是在 `RequestAttempt` 里直接不接**：守护吞 `disconnectSeq` 只认 `softLoginResult` 的 **0→1 上升沿**（`hangup_schedule.cpp`）。若早退在 `SetHold` 之前，hold 保持 0 撞上 `disconnectSeq` 上涨，守护走 `reloginHardFailed = kHardFailServerKick` → 干净重拉，把正在逛拍卖的客户端直接杀掉 —— 与 §2.4.1 同一个坑。

**判据禁忌**：

- **不得**改用 `why` 字符串或会话状态来认拍卖：服端**拒绝**野外迁移时（`GlobalMarketTerminated`，op 398）是**真断线**，`why` 与状态和成功迁服完全一样，只有场景态分得开这两种情形。
- **不得**额外要求 `IsAlive()`（WM→CharacterData→CharacterStat）作为佐证：市场场景下角色数据是否留存未经实测，加上去可能让出口**永不触发**（与 §2.4.4 的 `hallReady` 同类错误）。场景态本身已由 `ReadSceneStateRaw` 夹在 0..5 且 `GetWorldManager` 会对失效 WM 重解析，`channel_hop` / `encounter` / `player_hide` / `invuln` 也都只凭这一条判。
- **误判可自愈**：大厅 WM 兜底 + **断线窗轮询**（`dialog_linger`）。窗还在且已进过图，不必再等边沿。

**范围外**：长时间逛拍卖仍可能触发守护**另一条**路（不在图、无经验）的重拉，那是 `auction_town_bypass.h` 早已记载的「守护模式建议关绕过」，与本节的踢线边沿判据无关。

日志指纹：`in_market skip_teardown tag=… scene=5` / `RESULT success in_market skip_teardown`。

### 2.5 泵 idle / `pump_dead`（勿立刻交守护）

断线 InterStage 常见 **数秒** MainPump 无心跳（`IsPumpTicking` 假）。旧逻辑把 `connect_wait_pump_dead` / `reenter_pump_*` 标 **fatal → soft_fatal_no_retry → 立刻放 hold**；B9B（2026-08-10 08:32）约 2.5s idle 后游戏自连，软连已交守护 → 干净重拉，体感「乱杀」。

| 约定 | 值 / 行为 |
|---|---|
| `kPumpWaitBeforeSoftMs` | **20s** soft cycle 开头等泵 |
| `kPumpWaitConnectMs` | **20s** connect/reenter 满 streak 后再等一窗；活了清 streak 继续 |
| `kConnectPumpFailMax` | **40** |
| `kReenterPumpFailMax` | **48** |
| soft cycle | 泵类失败 **允许** 重试至 `kSoftCycleMax`（**10**）；用尽才 `Finish(2)` 放 hold |
| 禁止 | 把短暂 `pump_idle` 当 `soft_fatal_no_retry` |

日志指纹：`pump_wait` / `pump_revived` / `soft_cycle_retry`（不应再出现 `soft_fatal_no_retry`）。

## 4. 干预边界（是否过多插手游戏流程）

> 结论（2026-08-08 BIN）：**进图链仍是游戏 UI 正规路径**；历史上「过多」主要出在 **关窗扫面过大**（已收）。默认关，属 opt-in。

| 干预点 | 必要？ | 现状 |
|---|---|---|
| ConnectLogin | 游戏未自连时需要 | 已 Connected+登录 UI → **跳过** |
| dismiss 断线窗 | 避免点「確認」踢登录 | **CloseDialog** + Util/Ex/Notice 白名单 FindAll（实例 hook 已撤） |
| RequestRestart + softFast | 自动重进选区选角 | 官方按钮语义；缩短 settle，不改发包路径 |
| SoftPumpCall High | quiesce 下否则软连失败 | 仅 soft 短任务；不抬玩法 Low |
| softLoginHold | 防守护杀进程 | 成功/失败即放 |
| 进图后 post-dismiss | ~~曾误杀小地图~~ | **已禁**（inMap skip） |
| hall 重进 dismiss | 残留 Notice | 仅 Util/Ex，约每 2s 一次 |

**仍算「插手」、但可接受**：

- settle 窗内 **最多 1 次** 关窗 FindAll，其余轮只 Sample NM（最长 ~600ms）——只打 Util/Ex/白名单。
- softFast 比人手快点选区选角——仍走同一套 UI Job，不叠 opcode。
- InterStage 期间 High 入队——与换频同级约定；失败则整轮软连不可用。

**明确禁止的捷径**（未做、也不应做）：跳过 PickWorld、`TriggerEnterChannel`、点踢线 Yes/Ok、清浏览器登录态。
