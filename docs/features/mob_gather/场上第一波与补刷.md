## 0. 一句话

服端掐的是 **这只 oid 的移动包相对上一包（及刷点）的位移**，不是客户端 `_summonType`。

## 2. 为什么第一波「怎么吸都没事」

进图（或软重连回图）时，服端把 **当时还活着的 oid + 当前位置** 打进 `OnPacketMobEnterField`。这批怪的上一包位置已经和场地对齐。再吸，移动包只是从「已经认过的点」往人前挪。

位移夹速（默认开、48 px/帧）把逐帧预测位移压在「怪速+10」附近，客户端 `SendMobPrevPosHack` 发不满；服端族 A 自量包内位移也不容易一次破门。BIN 上第一波可以 `r=18650`、`maxCmd≈4800`、hop 过千 px，仍不立刻 205。

**没有**「第一世代豁免旗」的服端二进制。不能写成 vac 合法。边界：

- 位移夹速当时是开的；`impact disp=250–430 big=1` 仍出现在 hop 首帧，只是第一波没攒到踢。
- 高度谎（人在台上拖坑底 / `|dY|` 过大）是另一条，与世代无关（`kGatherMaxBelowPlayerPx` 尸检 ~1150）。
- 开了「清怪重连」时，第一波打完就 `CloseSession`，本会话根本不吸新 oid。

## 3. 为什么补刷危险

新 oid 的原位是 **刷点**。`EnterField` 之后立刻 Arm 远拉，第一串移动包 ≈ 刷点→人（几百到几千 px），族 A 被放大。  
平行检测文 §9：`gSpawnGateOn` 之后从 spawn 再拽，放大位移包。type21 被动插值 **不是** 这条 205 的元凶（节流 5 分钟，吸怪走主动 Flush）。

本仓进图第一批标 `exempt`（`gSpawnGateOn==0` 时见到的 oid），允许未横移就远拉；**第一次 `pushed>0` 之后 `gate=1`**，之后新 oid 走履历闸（贴地、非掉落，可选横移 `walkDx`）。这是补刷对策，不是 `_summonType`。

## 4. 只吸场上的 · 已落地行为

- 勾上当拍（及换图 / `nm_down` / `no_flight` / 软重连 hold / 延时钟 `since==0`）`ClearFieldSnap`，下一拍活怪 `NoteFieldOid`，`onField latch n=`。
- 快照外、且未武装 → `skipGen=` / `why=gen`。已武装可维持。
- **同图软重连 oid 全换**：不清快照会拿旧 oid 滤新场。BIN 01:43：`latch n=40` 后 `why=gen skipGen=28/40`。修完：`onField snap clear n=` → 再 `latch` → `pushed>`。
- 关勾：出场 / 新刷都不挡（仍走履历闸 / 高度闸 / 夹速）。

BIN（2026-08-24 `105070000`）：清怪重连 + 重连换频时 `reconnect-hop why=mob_gather_clear` 会换列表 id（游戏「頻道」= id+1），不是 F10 图内迁频。

## 6. 若要吸第二世代（未落码 · 2026-08-24）

目标：同会话里，第一波打完后 **新刷出来的 oid 也吸**，且尽量不 205。  
**禁止**再拿 `_summonType` 当门。

### 6.1 已经能做到、不必改吸怪闸

**清怪重连 + 只吸场上的**：这波死光 → 拆会话 → 回图重新 latch。登录期间图上新刷的怪，回图时算 **本会话第一波**，不是同会话补刷。  
换频勾上则进异频（BIN `stickyCh` / `PickSticky` / `GoWorld armedCh=`）。  
这是「换会话把补刷变成第一波」，不是「同图连续吸regen」。

### 6.2 同会话真吸补刷 · 候选（未拍板）

| 方案 | 做法 | 利 | 弊 / 未钉 |
|---|---|---|---|
| **A 放开快照，走履历闸** | 勾掉「只吸场上的」 | 零开发；贴地+横移后再拉 | 远刷点仍可能一次拉穿族 A；第一波与补刷飞控相同 |
| **B 人过去，不远拉** | 寻簇 / 巡点飞到补刷堆，只吸脚边 | 包内位移小 | 人要飞；与「站着吸」体感不同 |
| **C 补刷专用夹速 / 禁 hop / 禁策略 B** | 非 exempt 更小 `dispCap`、不许 hop、不许 fh-snap | 对准族 A | 吸得慢；hop 首帧 `big=1` 仍可能漏 |
| **D 离刷点总位移封顶** | `\|Ap-home\|` 超 ~800–1150 不新 Arm（home=第一次见到） | 硬限制「从 spawn 拉多远」 | 远点永远不吸，要配合 B |
| **E 存活时间窗** | oid 见到后等官方 AI 走 N 秒再 Arm | 让服端先有「正常」履历 | N 未标定；等太久漏刀 |
| **F 等 Active 再拉** | 等 `ctrl>0` / 280 | 像官方接管 | 公开图常年 `ctrl=-1`，可能永远等不到 |

倾向组合（讨论用，**未授权改代码**）：同会话要吸补刷 = **A 或放宽快照** + **履历闸必须开** + **C 或 D 至少一条**（禁止补刷 hop / 策略 B；或限制离 home 总距）。人愿意飞则 B 最稳。

### 6.3 不要走的路

- 用 `st=` / CMS Normal·Regen 当收怪条件（TW 场怪 `st=0`）。
- 补刷策略 B 一帧写落点（已证远距断）。
- 钩 `calc_priority` 谎报、造 206、写 `0xE8`。
- 把 type21 / 包裹 UI 的 926–928 当补刷 205 的修法。

### 6.4 若落码，BIN 怎么验

同图、勾掉「只吸场上的」或新模式，第一波打光后等刷：

- 应先见 `gate=1 skipSpawn=` / `skipAir=`，上台后再 `pushed>`，不应一刷出就 `maxAd` 上千。
- `impact disp=` 补刷段应长期 ≤ `cap`；不应连续 `big=1`。
- 30s 无 `pendingError=205`。对照：故意一刷出就 hop 远拉，应比「走完再慢吸」更容易 205。
