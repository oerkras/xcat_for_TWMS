# drop_alert_bypass Feature 模块设计（Classic TWMS）

> **状态**：✅ 已挂入（**v2 数据面** · 产品语义已定）  
> **源码根**：`x/features/drop_alert_bypass/` · IPC：`x/ipc/payload_control.*` · 契约：`common/xcat_payload_control.*`  
> **产物**：`bin/XCat_data/xcat.dll`（CMake `xcat_probe`）  
> **对照**：枫星 `drop_alert_bypass`（Lua `IsAlert` / `StartAlertAt`）；本仓不搬 Lua  
> **产品**：经典版 TWMS · **不是**枫星  
> **安全**：禁止 E9 / 改 GA `.text`；**不**占硬件断点槽

## 根因（BIN · 为何 MethodInfo「装上了但不生效」）

| 证据 | 含义 |
|---|---|
| `x.jsonl` 多次 `installed CanPerformAction … enabled=1` | MI 交换成功 |
| GA 内 **8× `E8 → CanPerformAction(0x4C2C40)`**，前序 `mov dl,1` | 丢物路径**直调 native**，不经 MethodInfo |
| `CanPerformAction` → `call` 短 `IsAlertMode` **`0x12405C0`**（`cmp [rcx+114h]` / `0x14859CC3`） | 真正门控字段仍是 **`LocalUser+0x114`** |
| 08-03 remount 误钉 CFF 兄弟方法 `0x1242770`（读 `+0xC8`） | 清错字段 → BIN `was=0`、丢物仍拒；**已改回** |
| `channel_hop` 共用同一短 `IsAlertMode` RVA | 字段语义交叉验证 |

故 v1 只换 MI → 日志绿、行为不变。

## v2 方案（现行 · 预期行为）

**主路径（数据面 · hold）**：功能开时读 `LocalUser+0x118`——非 0 则清零并保持 ~32ms 快拍；已是 0 时先继续快拍，**连续 8 拍（≈256ms）仍为 0** 才升 ~1s 慢校验（对齐拍卖 hold，且避免「刚清→立刻 1s 睡→出刀刷戳拒丢」）。出刀再刷戳时 streak 清零、退回快拍。

> 锚点：`kRvaIsAlertMode`（现行 remount 见源码）· `kOffAlertAt`（field hash → fallback `0x118`）· `CanPerformAction` MI 次路径。  
> **勿与** 旧误锚 `+0x114`（同类 bool）或 [`pet_loot/P0b`](../pet_loot/P0b_Drop归属预筛.md) 的 **`WorldManager+0x114`** 混淆。

**产品语义（有意为之，不是副作用）**：

- 战斗中可丢物（本地门控放开）
- **同时抑制客户端警戒态**（打怪后警戒立不住 / 很快解除；依赖 `IsAlertMode` 的本地逻辑一并按「不在警戒」走）
- **不**改服务端 Drop 权威；保护物确认 / 交易封锁等其它检查仍在
- 与 `channel_hop`「等待自然出警戒」不同：本功能是主动清字段；开着时 hop 侧也会看到「不在警戒」

**不做**：HWBP 改 `bCheckAlert`（简单功能不占 DR 槽）；**不做**「拦 UpdateAlert* 一次装稳」（无单一 MI 可达写入漏斗，见会话结论）。

**运行时防漂（shape gate）**：读短 `IsAlertMode` 机码，须同时命中

- `mov eax, imm` + `add eax, [rip]`
- `cmp [rcx+alertOff], eax`（`alertOff` 来自 field hash / `0x118`）

不匹配 → **拒绝清字段** + 锚点灯 `DropAlert=MISS` + BIN `shape FAIL`。匹配 → 照常 clear/hold，灯 `shape+118`。

**次路径**：保留 `DragManager.CanPerformAction` MethodInfo 交换（少数 MI 调用方）；日志 `miHits` 预期长期为 0。

```
QueryCombatCtx(MyUser)
  → read +0x118
  → ==0: streak++; streak>=8 → hold 1s；否则仍 32ms
  → !=0: clear to 0; streak=0; 32ms
```

## 控制面

| 项 | 值 |
|---|---|
| INI | `[core] dropAlertBypass`（默认 **0** / 关） |
| UI | 实验 Tab「战斗中可丢物」+ tooltip 说明抑制警戒 |
| 日志 | `[DropAlert] field clear …` / `hold-cand … streak=` |

## 验收

1. 开功能 → 可丢物；客户端警戒被抑制；日志 `shape OK` + `field clear` / `hold-cand`  
2. 换版后若机码漂移 → BIN `shape FAIL`、灯 `DropAlert=MISS`、**不再清字段**（需重锚）  
3. `miHits` 可为 0（正常）  
4. 关功能 → 警戒恢复正常时长；警戒态再次拒绝丢物  
5. 保护物/交易封锁确认仍在  
6. 边打边丢：不应出现「清完后约 1s 才又能丢」；挂机不打时应出现 `holding=1` 慢扫
